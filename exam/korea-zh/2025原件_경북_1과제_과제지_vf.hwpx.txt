3. VPC

参考以下说明和 Reference01 的表格，配置 VPC。在运行 Application 的 Subnet 中，配置为 Image Download 时只能经由内部 Network 下载。（必须使用 ecr.dkr、s3 Endpoint。）
4. VPC 之间的 Peering
该 Architecture 中，Network 被分离为 2 个 VPC。各 VPC 必须能够相互通信，应用才能无问题地处理来自外部的请求。为使各 VPC 相互通信，使用 Peering Connection。
peering connection name: skills-peering
5. Network Firewall<hp:lineBreak/>
配置 Network Firewall，以过滤通过 IGW 进入 VPC 内部的流量以及从 Bastion 发出的流量。通过 IGW 进入的流量，以及 VPC 内部通过 IGW 出去的流量，都必须经过 Network Firewall 所在的 Inspection Subnet。请充分考虑经过 PCX、IGW、NAT 等的流量走向，配置 Route table 的 Route。
network firewall name : skills-firewall
network firewall policy : skills-firewall-policy
network firewall subnet : skills-inspect-subnet-a, skills-inspect-subnet-b
5-1. Network Firewall Rule
<hp:lineBreak/>
配置以下规则，以便按条件阻断流量。
阻断从 Bastion 发往外部 ifconfig.me 的 HTTP/HTTPS 请求。
6. Bastion Server
为了评分，使用 AWS EC2 创建 Bastion Server。必须配置为即使重启，IP 也不会变更，以免评分过程中 IP 突然变更。SSH 访问时，考虑到安全性，必须将 Port Number 更改为 2025。必须在 skills-hub-subnet-a Subnet 中运行。评分时以 Root user 进行，因此不能有 Package 相关错误，并且 IAM Role 仅使用 AdministratorAccess Policy 进行配置。必须能够通过 GitHub CLI 访问账号及 Repository。此外，将 Bastion EC2 配置为可以使用 KeyPair 及 Password 认证两种方式访问。
Bastion Server 用于评分。
如果配置错误，可能会在特定评分项目中受到不利影响，请注意。
Instance Name Tag : skills-bastion
Machine Image : Amazon Linux 2023
Instance Type : t3.small
Security Group Name Tag : skills-bastion-sg
IAM Role Name Tag : skills-bastion-role
Login Password : Skill53##
Required Package : awscliv2, curl, jq, eksctl, kubectl, argocd cli, gh cli
7. Secret Store
将用于连接 Application Database 的环境变量保存到由 KMS 加密的 Secrets Manager 中进行管理。环境变量值不得直接指定到 Pod 中，必须配置为仅通过 Secrets Manager 中保存的值加载。（Environment Variables 详细信息请参考 Reference02）
Application Secret Name : skills-secrets
8. Application
共有 Green、Red 两个 Application。提供的 binary 使用 golang/gin 开发，并在 x86 系统上构建。Application 运行时绑定的 Port Number 是 TCP/8080。此外，2 个 application 都通过 /health 检查 Application 状态。（Application 详细信息请参考 Reference02）
9. RDBMS
为了稳定高效地保存 Green、Red Application 数据，配置 RDBMS。使用 AWS 托管的 MySQL 兼容引擎，并以 default for major version 8.0 构建 Database。为方便 DB 管理，必须启用 Logging、Monitoring、Backtracking。此外，配置为可从 Bastion Server 访问 RDS。
DB Cluster Name : skills-db-cluster
Master username : admin
Master password : Skill53##
DB instance class : db.t3.medium
DB Name : day1
10. S3 Bucket
为了轻松管理 ArgoCD 的应用程序，配置为使用 S3 Bucket 及 Helm Chart 管理 Manifest。此外，将用于评分的 v1.0.1 binary 上传到 S3。
Bucket Name : skills-chart-bucket-<英文 4 位>
App Chart : s3://skills-chart-bucket-<英文 4 位>/app
v1.0.1 Binary Path : s3://skills-chart-bucket-<英文 4 位>/images/
11. Container Registry
将提供的 application 制作成 Image 后，保存到 AWS ECR Repository。上传到 ECR 的 Image 必须能够进行 KMS 加密和漏洞分析。不得存在漏洞。此外，以 v1.0.0 Tag 上传，并配置为如果存在相同 Tag 则无法上传。为了评分，在容器中安装 curl。
Green image repository Name : skills-green-repo
Red image repository Name : skills-red-repo
12. Continuous Delivery<hp:lineBreak/>
通过自动化应用程序的部署过程来提高工作效率，配置 CD 环境。首先，利用 S3 及 Helm Chart 配置 ArgoCD Application。Application 的 Chart source 使用 s3:// 格式的 S3 URI。配置一个名为 app 的 Chart，并在 GitHub 中创建名为 day1-values 的 Public Repository。在 day1-values 中分别编写用于 green、red 应用的 values 源，并据此配置 2 个名为 green、red 的 ArgoCD Application。在 ArgoCD 中 Sync 时，应用也必须根据 GitHub Repository 的 values 中指定的内容进行变更。但是，不能使用 githubusercontent、GitHub Pages 来获取 values。<hp:lineBreak/>（为了评分，将使用 v1.0.1 binary 的 Dockerfile 分别放置在 /home/ec2-user/images 文件夹下的 green、red 文件夹中。）
Green Values File Name : green.values.yaml
Red Values File Name   : red.values.yaml
13. Container Orchestration
为了将提供的 Application 部署到 Container 环境，使用 AWS EKS。必须能在 CloudWatch Logs 中查看 EKS Cluster Control Plane 产生的所有日志，并且 Secret Resource 必须进行 KMS Encryption。此外，Kubernetes API 必须无法从外部访问，并且只能从 Bastion Server 访问。为便于管理，所有 NodeGroup 都创建为 Managed NodeGroup，必须考虑最低限度的高可用性，并且 NodeGroup 必须在 Private 环境中运行。给定的 application 必须使用名为 skills 的 Namespace，在 EKS Cluster 内进行逻辑隔离。由于可能会部署新 Version 的 EKS Pod，必须考虑零停机部署进行配置。
EKS Cluster Name : skills-eks-cluster
EKS Cluster Version : 1.32
Application Managed Nodegroup
Application 必须在 Application NodeGroup 中运行。不得存在除此之外的其他 Resource，并且必须考虑高可用性。此外，该 NodeGroup 的 Node 必须具有 {skills:app} 这个 Label。
NodeGroup Name : skills-app-nodegroup
Node Instance Name Tag : skills-app-node
Node Instance Type : t3.medium
Addon Managed Nodegroup
除 Application 之外的 AWS Load Balancer Controller 等 Addon 必须在 Addon NodeGroup 中运行。必须至少运行 2 个以上。此外，该 NodeGroup 的 Node 必须具有 {skills:addon} 这个 Label。
NodeGroup Name : skills-addon-nodegroup
Node Instance Name Tag : skills-addon-node
Node Instance Type : t3.medium
Fargate Profile
为了部署 CoreDNS，使用 Fargate。除 CoreDNS 之外，其他资源不得存在于 Fargate Profile 中。
Fargate Profile Name : skills-fargate-profile
Label : {skills:coredns}
EKS Deployments
green Application Deployment Name : green-deploy
red Application Deployment Name : red-deploy
14. Logging

为了收集 Application Log，使用 OpenSearch。为了收集日志，配置 Fluentd 从 Fluent Bit 接收日志并存储到 OpenSearch。Fluentd 必须按 Application Nodegroup 的每个节点运行 1 个 Pod 的方式运行，Fluent Bit 则配置为在应用程序 Pod 内以 Sidecar 方式运行。OpenSearch Dashboard 必须能够通过 Web 浏览器访问。此外，配置为不传递 /health 路径的日志。
加载到 OpenSearch 的日志应以 JSON 格式解析并存储，且必须排除 /health 相关日志。（日志格式详细信息请参阅 Reference03）
域名 : skills-opensearch
版本 : 2.19
数据节点实例类型 : r7g.medium.search
数据节点数量 : 2
主节点数量 : 3
主用户名 : admin
主密码 : Skill53##
索引模式 : app-log
15. 负载均衡器<hp:lineBreak/>
为了能够从外部顺畅且安全地访问 Green、Red 应用程序，按照以下要求配置负载均衡器。必须能够使用 VPC Endpoint，通过 PrivateLink 在不经过互联网的情况下进行 NLB 之间的通信。<hp:lineBreak/><hp:lineBreak/>
15-1 Internal ALB
配置 Application Load Balancer，以便从内部安全地访问应用程序，并能够基于 L7 提供的各种数据分发请求。
负载均衡器名称 : skills-alb
负载均衡器方案 : internal 
负载均衡器类型 : Application Load Balancer
负载均衡器监听 : HTTP 80
15-2 Internal NLB<hp:lineBreak/>
配置 Internal 类型的 Network Load Balancer，以便 External NLB 能够通过 VPC Endpoint 安全地访问应用程序。
负载均衡器名称 : skills-internal-nlb
负载均衡器监听 : TCP 80
15-3 External NLB<hp:lineBreak/>
配置可从外部访问的 Network Load Balancer，以便 Hub VPC 能够通过 VPC Endpoint 安全地与 Internal NLB 通信。
负载均衡器名称 : skills-nlb
负载均衡器方案 : internet-facing
负载均衡器监听 : TCP 80
