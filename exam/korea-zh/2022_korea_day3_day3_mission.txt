3. Docker 问题
使用提供的 Dockerfile 创建镜像后运行时，会输出无法执行启动命令所指定文件的问题。请解决此问题。最终，容器运行后必须执行 /opt/app/app.py。应用程序文件的位置或文件内容不得更改。
调用 /health API 时，必须能够收到响应码 200 以及源代码中指定的 body。
创建名为 day3 的 EC2，构建修改后的 Dockerfile，然后用该镜像运行服务器并保持运行。在 day3 服务器上调用 localhost:80 HTTP 时，必须返回容器 Flask 服务器的响应。该问题的评分项之一是通过 docker ps 命令确认 docker 进程是否正常运行。容器内部必须使用端口 8080。
- 所提供的文件中使用的文件：Dockerfile, app.py

4. AWSCLI 问题
提供的 shell script 中存在无法执行 awscli 的问题。请解决此问题。最终必须显示服务器 S3 文件的名称和大小。文件共有 3 个：a.txt、b.txt、c.txt。将文件放置在 day3 EC2 的 /opt/cli.sh 位置。为对第 4 题问题进行评分，将检查存储桶创建以及上述文件上传。执行 /opt/cli.sh 脚本时，必须通过 uuidgen 自动创建 skills-korea-2022-<random> 存储桶。并且必须将上述 3 个文件自动上传到所创建的存储桶中。不得修改 cli.sh 文件中第 1~5 行、18~22 行的内容。
- 所提供的文件中使用的文件：cli.sh

6. CloudFormation 问题
使用提供的 C.F 创建 VPC 时会输出错误。请修改。任务结束前，请删除通过该 C.F 创建的所有资源。评分时会直接执行 C.F 文件进行测试，因此如果事先已创建，可能会发生错误导致无法评分。必须将该文件放置在 day3 EC2 的 /opt/cf.yaml 位置。评分时会使用如下命令之一：
aws cloudformation deploy --template-file /opt/cf.yaml --stack-name <임의값>
并且在 CloudFormation Stack 部署后，将使用以下项目之一进行评分。
- NAT G/W 是否已分配 EIP
- 是否使用 Parameters 中的 CIDR 和 Tag 信息配置了 subnet
- Public subnet 是否已正确分配 Public route table
- Private subnet 是否已正确分配 Private route table
- Public route table 是否已正确分配 NAT G/W
- Private route table 是否已正确分配 IGW
- 所提供的文件中使用的文件：cf.yaml
