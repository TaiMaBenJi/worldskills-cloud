2. 选手注意事项

  1) 使用机械及工具等时请注意安全，必要时请佩戴安全装备及穿着防护服等，以预防事故。

  2) 工作中请注意预防烫伤、触电、擦伤等安全事故，使用工具或作业工具时请遵守佩戴安全防护用品等安全规程。

  3) 工作中请注意工具的使用，遵守安全规程，预防事故。

  4) 比赛开始前请通过轻度拉伸等放松紧张情绪，使用作业工具时请注意安全。

  5) 选手的账户存在费用限制，若产生高于该限制的费用，账户可能无法使用。

  6) 题目中给出的尖括号 <> 表示变量，选手需适当更改后使用。

  7) 任务结束时，请终止所有正在进行的测试，以免给服务器造成负载。

  8) 如无特别说明，请在 ap-northeast-2 区域创建资源。

  9) 第1页的图是对构成的抽象表示，具体构成应能够满足以下需求事项。（例：子网可能存在2个以上。）

  10) 所有资源的名称、标签、变量均区分大小写。

  11) 题目中未给出的值，应依据 AWS Well-Architected Framework 6 pillars 设定为合适的值。

  12) 创建不必要的资源可能成为扣分因素。
（例如：未使用的 EC2、额外添加的 VPC、在其他区域创建资源等）

  14) 所有时间均使用 KST(UTC+9) 时区。

  15) 计算类型只能使用 EC2 实例。无论出于何种目的，均不得使用 Fargate 和 Lambda。

3. 关系型数据库

 user 应用程序使用关系型数据库，且读取、写入操作均须可用。应用程序支持 MySQL Community 引擎。DB 实例以最小规模运营。

 - DB identifier : apdev-rds-instance

 - Deployment options: Multi-AZ DB instance

 - DB instance class: db.t3.micro

 - Storage type: General Purpose SSD (gp3)

 - Engine : MySQL Community 8.0

 可参考以下命令创建表。



CREATE TABLE user (

    id               VARCHAR(255)    NOT NULL,   

    username         VARCHAR(255)    NOT NULL,

    email            VARCHAR(255)    NOT NULL,

    status_message   VARCHAR(255)    NOT NULL,

    PRIMARY KEY (userid),

    UNIQUE KEY uk_username (username)

);

 为确保正常运行，必须使用 load_user.dump 文件插入数据，插入的数据请勿任意修改或删除。请注意，插入除产生流量之外的其他任意数据可能导致性能下降。可能需要根据应用程序的行为和流量模式重新设计表结构。

7. 流量处理

 构建系统，以便部署应用程序并向外部用户提供服务。必须使用容器，容器编排工具使用 ECS。不能使用 EKS。容器镜像仓库可以使用 ECR，用于容器托管的计算资源使用 EC2。

 EC2 实例仅使用 t3.medium 类型，并且为处理流量仅使用最少的资源。如果使用其他实例类型或使用过多资源，可能会导致扣分。

 为处理流量，将提供给用户的 Endpoint 统一为一个。从比赛开始 1 小时后开始产生流量，并通过输入到评分平台的 Endpoint 注入选手的系统。处理比赛期间产生的流量，使其满足目标服务水平。构建监控环境和日志解决方案，以执行日志分析、流量模式分析、系统改进、系统故障/错误检测与应对。不要让本人的 Endpoint 暴露给他人，以免遭受不利影响。输入到评分平台的格式为协议和地址（IP/DNS），不得写入路径。

- 正常示例: https://example.org
- 错误示例(1): example.org（缺少协议）

错误示例(2): https://example.org/v1/（填写了路径）

 确保可用性，以便无服务中断地稳定提供服务。应考虑到这一点来设计、构建并运营系统。

 对发往提供给用户的 Endpoint 的非正常请求进行 Block，并返回 403 响应码。但除提供的 API 之外的请求应返回 404 响应码。
