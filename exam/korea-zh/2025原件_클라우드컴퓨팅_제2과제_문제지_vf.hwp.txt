3. NoSQL DataBase

Module: 2) NoSQL

该 Module 在 ap-northeast-2 中进行。使用 DynamoDB、Lambda 构建实时全球交易账户系统。详细事项请参考以下内容进行配置。

NoSQL 配置

利用 DynamoDB 构建实时全球账户汇款系统。PK 设置为 account_id。表配置为 Global Table，使 ap-northeast-2 和 eu-central-1 两个区域实时同步。

Python 应用程序部署到 EC2，并提供账户创建(/create_account)、汇款(/transfer) API。处理汇款时使用 TransactWriteItems，从发送账户的余额中扣减金额，并向接收账户存入金额。当 balance >= amount 条件不满足时，事务必须失败并返回错误。

发生同步冲突时，使用 Conflict Resolution Lambda 自动恢复为最新数据。配置为在事务失败率及冲突发生时通过 Lambda 恢复问题。

为应对数据丢失，启用 PITR，使表可随时恢复到之前的时间点。

- DynamoDB Table Name: account-table

- Lambda Function Name: account-conflict-resolver

EC2 Instance Name: account-app-ec2

EC2 Instance Type: t3.micro

事务配置

Python 应用程序在汇款请求时使用 TransactWriteItems 防止并发问题，并在条件失败时返回适当错误。发生同步冲突时，Lambda 执行自动恢复逻辑。发生冲突事件时，通过 Lambda 自动解决问题。

Application

提供由 Flask 构成的应用程序 app.py。该应用程序使用 TCP 8080 绑定，详细事项请参考以下内容。

| Path | Method | Request Body |

| /transfer | POST | { "from_account": "cloud", "to_account": "it", "amount": 500 } |
| /healthcheck | GET | - |

4. Edge DRM

Module: 6) CDN

该 Module 在 us-east-1 中进行。使用 CloudFront、Function 及 Lambda 实现 Edge DRM。详细事项请参考以下内容进行配置。

Edge DRM 配置

利用 Lambda 及 Cloud Function 实现 Edge DRM 功能。S3 Bucket 配置为 web-drm-bucket-<任意3位数字>。将 *.mp4 上传到 S3 Bucket 的 media/。用户通过 CloudFront Domain 请求应用了 DRM 的视频，请求时必须通过 Query String 参数包含 DRM Token。利用 Function 在 Viewer Request 阶段读取 Query String 中的 DRM Token 值，并将该值插入为 X-DRM-Token Header。

当请求传递到 Origin 时，利用 Lambda@Edge 在 Origin Request 阶段验证 X-DRM-Token Header 值。仅当 Token 有效时，才从 S3 获取原始媒体文件并输出；当 Token 不存在或无效时，配置为 Lambda@Edge 立即返回 403 Forbidden 响应。

DRM Token 值必须包含在 Cache Key 中，以便按用户分离缓存，Cache TTL 设置为 60 秒。请注意设置 Cache Policy，以免用户 Token 混入其他用户的缓存结果。

DRM Token: drm-cloud

CDN 配置

配置以 CloudFront 为 Origin 的 CDN。当用户通过 CloudFront Domain 请求应用了 DRM 的媒体时，在 Viewer Request 阶段使用 CloudFront Function 从请求 URL 的 Query String 中提取 DRM Token 值，然后将 X-DRM-Token 值插入请求 Header。之后由 CloudFront Cache Server 管理包含 DRM Token 值的缓存；当请求传递到 Origin 时，利用 Lambda@Edge 验证 DRM Token，如果不合适则必须返回 403 响应。

当 CloudFront 向 Origin 发送请求时，如果请求的文件存在于 S3，则原样返回；如果不存在，则返回 404 Not Found。将 DRM Token 设置为较短的 TTL 以提高安全性，DRM Token 的有效性验证逻辑使用 Lambda Runtime 的 Python3.13 实现。使用 CloudFront Function 时使用 cloudfront-js-2.0。

CloudFront Name: web-cdn

CloudFront Function Name: web-cdn-function

Lambda Function Name: web-drm-function

模块：13) WAF

该模块在 us-west-1 中进行。使用 AWS WAF 进行配置，以防御 XXE 攻击方式。

应用程序

| Path | Method | Query Paramater |
| --- | --- | --- |
| / | GET | - |
| /parse | POST | ex) xml=<note><msg>Hi</msg></note> |

EC2 配置

使用 EC2 运行给定的应用程序。VPC 使用 Default VPC。

EC2 实例名称：xxe-server

EC2 实例类型：t3.micro

ELB 配置

使用 ELB 通过 Endpoint 向用户提供运行了应用程序的 EC2。将 ELB 配置为可从互联网访问。

ELB 类型：Application

ELB 名称：xxe-alb

WAF

使用 WAF 防御给定应用程序的 XXE 攻击方式。配置为当攻击进入时返回 403 错误并输出消息“403 Forbidden error”，且考虑成本，WAF 的 Rule 只创建一个。

WAF 名称：xxe-waf

攻击方法

应用程序允许 XML 解析器解析外部实体，因此攻击者可以利用这一点执行各种攻击。首先，利用 file:// 协议尝试读取并窃取服务器内部敏感文件的本地文件包含攻击。接着，可以通过外部实体强制发起 HTTP 请求，执行访问 AWS 元数据服务等受保护的内部网络资源的 SSRF 攻击。此外，通过反复扩展嵌套实体的“Billion Laughs”攻击耗尽 XML 解析器的资源，引发拒绝服务（DoS）状态。将依次组合这些攻击技术，进行使应用程序失效或泄露内部信息的攻击。
