AWS saml SSO with Keycloak
使用 Keycloak 登录 AWS Console。需利用 AWS IAM 功能与 Keycloak 实现 saml SSO。搭建时，Keycloak 服务器设置相关部分均可自由配置。所使用的 VPC、容器方式、EC2 使用方式均不作限制。
但为降低费用，实例规格不得超过 t3.medium 左右的规模，
且所有资源都必须创建在选手的 AWS 账户中。此外，对于已创建或课题所需的 IAM 用户，不另行删除，并保持使用现有 IAM 用户登录的方式同样可用。

创建 Keycloak 用户
创建 2 个用于登录 AWS 的 Keycloak 用户。创建 admin<编号>、dev<编号> 两名用户。该用户并非 AWS IAM 账户，而是需添加到 Keycloak 的用户。（UI 可能因版本而略有差异，但必须是 Keycloak 页面。）

映射 AWS IAM role
在 AWS IAM 中创建两个 IAM Role：名为 admin-access 的 IAM Role 和名为 poweruser-access 的 IAM Role。两个 Role 的权限可自由分配 PowerUser 及以上级别的权限。
admin<编号> 用户访问用于登录 AWS 的 Keycloak 页面时，认证后应能够访问 AWS admin-access IAM Role。
dev<编号> 用户访问用于登录 AWS 的 Keycloak 页面时，认证后应能够访问 AWS poweruser-access IAM Role。
评分时将确认：能否访问 Keycloak 页面、Keycloak 登录后是否出现 AWS IAM Role 选择界面，以及两名用户能否通过认证分别以各自分配的 IAM Role 登录 AWS Console。
DNS 不是评分要素，但选手若认为需要也可创建。既可直接在 Route53 购买 DNS，也可接受第1课题中使用过的 cloudhrdk{0-2}.com DNS 的委派。若需购买或委派 DNS，请在比赛结束前1小时向评审组提出申请并办理。
