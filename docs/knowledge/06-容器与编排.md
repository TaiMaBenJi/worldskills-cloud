# 06 · 容器与编排（L6）—— Docker → Kubernetes → GitOps

> 世界赛 2022 之后的题面全面云原生化；韩国 2025/2026 全锦赛的主线就是 **EKS + Helm + ArgoCD + 监控 + SLO**。
> 中国国赛"容器云"模块（40% 权重）同样是 K8s。这是**含金量最高、也最容易拉开差距的一层**。

---

## 能力清单

- [ ] Docker：镜像构建（多阶段）、网络、卷、Compose，能解释每一层
- [ ] Kubernetes：从 Pod 到 Ingress 全对象模型 + 运维操作 + 排障三件套
- [ ] Helm：写 chart、模板化、发布/回滚
- [ ] GitOps：ArgoCD/Flux 全流程（含 private repo、Helm repo on S3）
- [ ] 在 EKS 上交付生产级服务：ALB Ingress、HPA、监控、日志、密钥注入
- [ ] 会用 Kustomize 管理多环境

## 知识地图

### 1. Docker 深潜
- 镜像/容器/仓库三概念；分层与缓存原理；unionfs
- Dockerfile 指令全解 + **多阶段构建**；`.dockerignore`；镜像瘦身
- 网络模式（bridge/host/overlay/macvlan）；卷与 bind mount
- registry：自建 harbor / ECR 推送（韩国赛必考：build → push ECR → 扫描）
- Compose 编排本地栈；`docker inspect/logs/exec/stats`
- 底层：namespace + cgroups（回看 01 章超前部分）

### 2. Kubernetes 核心（CKA 水平起步）
**对象模型**
- 工作负载：Pod / ReplicaSet / Deployment / StatefulSet / DaemonSet / Job / CronJob
- 服务与网络：Service（ClusterIP/NodePort/LB/ExternalName）、Endpoints、Ingress、NetworkPolicy、CoreDNS
- 配置：ConfigMap / Secret / **External Secrets Operator（韩国赛题明确要求）**
- 存储：PV/PVC/StorageClass/CSI（EBS/EFS）
- 调度：requests/limits、亲和/反亲和、污点与容忍、拓扑分布
- 伸缩：HPA / VPA / Cluster Autoscaler / **Karpenter（2026 韩国题出现）**

**运维技能**
- `kubectl` 全家桶：get/describe/logs/exec/port-forward/rollout/cordon/drain/taint/top
- 排障方法论：Pending→调度问题；CrashLoop→日志/探针；ImagePull→凭证/网络；DNS→CoreDNS
- RBAC：Role/RoleBinding/ClusterRole；ServiceAccount + IRSA
- 探针：liveness/readiness/startup 的差别与误用陷阱

### 3. 集群搭建与托管
- EKS：节点组（托管/自管）、Fargate Profile、**Pod Identity**（2026 题要求）、插件（CNI/CoreDNS/kube-proxy）
- 自建对照：kubeadm 单/多节点（理解原理用）
- 多集群视角：ArgoCD 多集群发布

### 4. Helm
- chart 结构（Chart.yaml/values/templates/_helpers）
- 模板函数、`--set`、版本与回滚、`helm package`/`helm repo index`
- **私有仓库**：helm-s3 插件（韩国 2026 第1任务：S3 上的 Helm repo + ArgoCD 拉取）
- 与 Kustomize 的取舍

### 5. GitOps（高分区分度）
- 原理：声明式 + 单一事实源 + 持续调和
- ArgoCD：Application/AppProject、sync policy、private repo 认证（**patch repo-server 挂 SSH key —— 韩国赛现场操作**）
- 发布进阶：Argo Rollouts（金丝雀/蓝绿）、同步波次
- Flux 对照；Sealed Secrets/SOPS 密钥管理

### 6. 运行时与网关
- Ingress Controller：AWS Load Balancer Controller（**TargetGroupBinding** 直接绑 TG —— 韩国 2025 题技巧点）、nginx-ingress
- Gateway API（下一代标准）
- Service Mesh 入门：Istio/Linkerd 流量拆分、mTLS（超前部分详见 10 章）

### 7. 可观测集成（与 08 章联动）
- Fluent Bit/Fluentd → OpenSearch/CloudWatch Logs（韩国赛：日志管道配置评分）
- Prometheus + Grafana + kube-state-metrics（韩国 2026 task1 要求完整监控栈上线）
- Loki + Promtail 轻量日志（2026 题出现 Loki 查询评分）

## 超前部分

- **Karpenter**：节点供应新范式（按需、混合容量）；2026 韩国题已考
- **Gateway API + Envoy Gateway**：Ingress 的继任者
- **Platform Engineering**：Backstage/内部开发者平台，把上述全部打包成自助服务
- **供应链安全**：SBOM（Syft）、镜像签名（Cosign）、SLSA 等级、准入控制（Kyverno/OPA）
- **运行时安全**：Falco/eBPF 威胁检测（ninejuan 的 eks-ai-threat-detection 仓库即此类）
- **多集群与混合**：Cluster API、Fleet（Rancher）、Karmada
- **Wasm 运行时**：runwasi/Spin，容器之后的轻量沙箱
- **GPU 调度**：为 AI 负载准备（NVIDIA device plugin、MIG、Kueue）

## 检验标准

1. 从零（kind）30 分钟：部署一个带 HPA、Ingress、配置/密钥、探针的完整应用
2. EKS 实战：ALB Ingress 暴露服务 + IRSA 访问 S3 + Fluent Bit 日志到 CloudWatch，全部验证
3. ArgoCD 全流程：Git 改动 → 自动同步 → 观察到滚动更新与回滚
4. 故障演练：把 Service selector 改错/资源限制调小/探针配坏，10 分钟内定位并修复
5. 解释题：为什么 Helm chart 的 targetRevision 必须与 package 版本匹配（韩国选手 checklist 原话）
