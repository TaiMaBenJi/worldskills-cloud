# 08 · 可观测性与性能工程（L8）

> 韩国锦标赛第3任务（40 分）几乎全是这一层：**SLO 达标 + 成本最优 + 异常处理**。
> 这是"运维"升级为"SRE"的核心技能，也是世界赛"Operational considerations"（10%）与"Performance and optimization"（10%）两个官方标准的落地。

---

## 能力清单

- [ ] 讲清监控三大支柱：指标（Metrics）、日志（Logs）、追踪（Traces）
- [ ] 搭完整监控栈：Prometheus + Grafana + Exporter 全家桶（node/blackbox/cAdvisor/kube-state-metrics）
- [ ] 日志管道：Fluent Bit → OpenSearch/CloudWatch；会在秒内定位一条错误日志
- [ ] 会写告警规则 + 理解告警疲劳；会做仪表盘
- [ ] 会压测（locust/ab/k6）并读结果：p50/p95/p99、RPS、错误率
- [ ] 能把"SLO 95% ≤ 200ms"翻译成架构决策（缓存/伸缩/连接池/索引）

## 知识地图

### 1. 指标体系（Prometheus 体系为主线）
- Counter/Gauge/Histogram/Summary 四类型；为什么延迟要用 Histogram
- PromQL：rate/increase/histogram_quantile/聚合/子查询（**比赛就考这几板斧**）
- Exporter 生态：node_exporter、blackbox_exporter（拨测）、cAdvisor、kube-state-metrics
- 告警：Alertmanager 路由/静默；PrometheusRule（**韩国 2026：HighLatency 告警规则评分**）
- 云侧对照：CloudWatch Metrics/Alarms、Container Insights（**韩国 2026 task1 明确评分项**）

### 2. 日志体系
- 采集：Fluent Bit/Fluentd（DaemonSet）、Promtail、CloudWatch Agent
- 管道配置：input/parser/filter/output；JSON 解析、多行日志合并（Java 栈）
- 存储/检索：OpenSearch/ELK、Loki（韩国 2026 有 Loki 查询评分）、CloudWatch Logs Insights
- 结构化日志规范、trace_id 关联
- **比赛实战**：把应用日志送进 OpenSearch 建 index pattern（韩国 2025 题评分点：app-log）

### 3. 追踪（Traces）
- OpenTelemetry 标准（SDK/Collector/OTLP）
- Jaeger/Tempo/X-Ray；采样策略
- 与日志/指标联动（exemplars）

### 4. 性能工程
- 性能测试方法：基线→负载→压力→浸泡→尖峰
- 工具：k6、locust（**韩国出题人用 aiohttp 自写 loadgen：混入正常/异常/恶意请求**）、ab、wrk
- 关键指标：吞吐、延迟分位数、错误率、饱和度（USE/RED 方法论）
- 瓶颈定位链条：网络→LB→应用→DB→存储；每跳的观察工具
- 优化手段实例：
  - 应用层：连接池、异步、缓存头
  - 数据层：索引（覆盖索引恢复——韩国 2026 提到）、读写分离、DynamoDB 键设计
  - 架构层：CDN、缓存、水平扩展、异步解耦

### 5. 可靠性与 SLO
- SLI/SLO/错误预算；比赛中的 SLO 是硬指标（≥90%/87.5%/…阶梯给分）
- 高可用模式：多 AZ、健康检查、自动故障转移、**蓝绿/金丝雀（WSOS 标准原文）**
- 容灾模式：备份/恢复、Pilot Light、热备多活（DR 分级 RTO/RPO）
- 混沌工程入门：故障注入→验证恢复（超前）

### 6. 成本工程（FinOps 入门）
- 资源 rightsizing、闲置检测、Savings Plans/RI/Spot
- 存储分层（S3 Lifecycle）、日志保留策略
- **成本可观测**：Cost Explorer、标签策略、单位成本（cost per request）
- 韩国赛"cost ratio"评分：平均节点数/2 —— 用 Karpenter 等弹性机制压低常态节点数

| 真题 | 用法 |

## 检验标准

1. 给一个"慢"的 Web 服务，用四层观察法（LB→应用→DB→主机）在 20 分钟内定位瓶颈并给出数据支撑
2. 从零搭 Prometheus+Grafana：3 个 dashboard（资源/应用/业务）+ 3 条有效告警（不能是噪声）
3. 跑一次完整压测：产出报告含 p50/p95/p99、错误率、饱和点与优化前后对比
4. 复现韩国 task3 评分脚本流程，拿到 30+/40 分
