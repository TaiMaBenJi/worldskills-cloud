# 第 6 章 · 负载均衡与高可用（让网站"打不倒"）

> 本章目标：一个网站只跑在一台机器上，机器一挂网站就没了。本章教你搭出"多台机器干活、挂一台不慌"的架构——这是所有正经系统的标配，也是世界赛 Module A 的大题（A12 评分点：HAProxy + VRRP）。
> 预计学习时间：1-2 周。

---

## 6.1 先搞懂两个词：负载均衡 & 高可用

### 负载均衡（Load Balancing）
**问题**：一个网站火了，一台服务器扛不住 100 万人的访问。
**答案**：多放几台服务器，让一个"调度员"把访问者**分流**到各台机器上。
> 比喻：超市 10 个收银台，有个引导员把顾客均匀指到空闲的收银台。

### 高可用（High Availability，HA）
**问题**：如果"调度员"自己挂了呢？
**答案**：准备两个调度员，一个主用一个备用；主的挂了，备用的**秒级接手**（对外表现：用户完全无感知）。

**两个都要，网站才真正"打不倒"。** 本章的组合拳：**HAProxy（调度员）+ Keepalived（主备切换）**。

---

## 6.2 演练环境（准备 3 台 Linux 虚拟机）

| 角色 | 主机名 | IP（举例） | 装什么 |
|------|--------|-----------|--------|
| Web 服务器 1 | web1 | 192.168.1.21 | Nginx |
| Web 服务器 2 | web2 | 192.168.1.22 | Nginx |
| 负载调度员 | lb1 | 192.168.1.30 | HAProxy |

> 只有一台机器？用 3 台？其实一台虚拟机里也能"假装"练：用不同端口跑 2 个 Nginx（8081/8082）当两个网站，用 haproxy 分发。**推荐真的开 2-3 台虚拟机**（VMware 里复制克隆很快），真实感完全不同。

### 准备两台 Web 服务器
在 web1 上：
```bash
sudo apt install -y nginx
echo "我是 web1" | sudo tee /var/www/html/index.html
```
在 web2 上：
```bash
sudo apt install -y nginx
echo "我是 web2" | sudo tee /var/www/html/index.html
```
（`tee` 命令 = 一边显示一边写文件，常配合 sudo 写系统文件。`echo xxx | sudo tee 文件` 是"sudo 环境下写文件的固定姿势"，因为 `sudo echo > file` 是不生效的——重定向是 shell 干的，shell 没有 sudo 权限。**记住这个技巧，面试常问。**）

现在：访问 web1 看到"我是 web1"，访问 web2 看到"我是 web2"。各是各的，还没分流。

## 6.3 HAProxy 实战：把访问"分"到两台机器

### 6.3.1 安装与配置
在 lb1（调度员）上：
```bash
sudo apt install -y haproxy
sudo systemctl status haproxy    # 装了但不急启动，先改配置

sudo cp /etc/haproxy/haproxy.cfg /etc/haproxy/haproxy.cfg.bak   # 先备份（好习惯！）
sudo nano /etc/haproxy/haproxy.cfg
```
把文件改成（删掉原来的，写这些）：
```haproxy
global
    log /dev/log local0
    maxconn 2000                    # 最大并发连接数

defaults
    log     global
    mode    http                    # 工作在 HTTP 七层模式
    timeout connect 5s              # 连接后端超时
    timeout client  30s             # 客户端超时
    timeout server  30s             # 后端超时

# ── 管理界面（浏览器里看流量统计）──
frontend stats
    bind *:8404
    stats enable
    stats uri /stats                # 访问 http://lb1:8404/stats 查看
    stats refresh 5s

# ── 主入口：接收所有访问 ──
frontend web_front
    bind *:80                       # 监听 80 端口（用户从这里来）
    default_backend web_servers     # 默认转发给下面的后端组

# ── 后端组：两台网站服务器 ──
backend web_servers
    balance roundrobin              # 轮询算法：你一次我一次，公平分配
    server web1 192.168.1.21:80 check    # check = 健康检查（挂了自动剔除）
    server web2 192.168.1.22:80 check
```
**逐段理解（这是 HAProxy 的万能模板）**：
- `frontend` = "从哪来"（监听端口）
- `backend` = "到哪去"（一组服务器）
- `balance roundrobin` = 轮流分配（还有 leastconn 最少连接、source 按来源 IP 等）
- `check` = 后台自动体检：某台机器不响应了，自动不再给它分流；恢复了自动加回来。

### 6.3.2 启动并验证
```bash
sudo systemctl restart haproxy
sudo systemctl status haproxy      # active

# 连续访问 6 次，观察分流效果：
for i in 1 2 3 4 5 6; do curl -s http://192.168.1.30; done
```
输出应该是：
```
我是 web1
我是 web2
我是 web1
我是 web2
我是 web1
我是 web2
```
**你一次、我一次——负载均衡成功！**

### 6.3.3 见证"高可用"的时刻
```bash
# 到 web2 上把 nginx 停了：
sudo systemctl stop nginx
# 回到 lb1，再连续访问：
for i in 1 2 3 4 5 6; do curl -s http://192.168.1.30; done
```
输出全是"我是 web1"——**HAProxy 的 check 发现 web2 挂了，自动不再分流给它。用户完全无感知！**
再启动 web2 的 nginx，等几秒，访问又恢复轮询。**这就是"故障自动转移"的第一次亲身体验。**

### 6.3.4 浏览器看统计面板
访问 `http://192.168.1.30:8404/stats`——能看到每台后端的连接数、健康状态、流量。**比赛和工作中，这个面板是你的"仪表盘"。**

## 6.4 Keepalived：让"调度员"也打不倒（VRRP 浮动 IP）

现在的问题是：HAProxy 所在的 lb1 挂了怎么办？用户连 192.168.1.30 就连不上了。
方案：再来一台 lb2（192.168.1.31），两台共用**一个"浮动 IP"（VIP）**——用户只访问 VIP（比如 192.168.1.100），谁活着谁就持有这个 VIP。

**VRRP 协议**（Virtual Router Redundancy Protocol）：两台机器不停"喊话"（组播心跳）——"我还活着！"。主的一旦哑了，备用的一秒内接管 VIP。**对用户来说，IP 没变，网站一直能用。**

### 6.4.1 双机配置
**lb1（主）**：
```bash
sudo apt install -y keepalived
sudo nano /etc/keepalived/keepalived.conf
```
```conf
vrrp_instance VI_1 {
    state MASTER               # 我是主（备用机这里写 BACKUP）
    interface ens33            # ★ 网卡名！用 ip addr 查你自己的（ens33/eth0/ens160）
    virtual_router_id 51       # 组号，主备必须一样
    priority 100               # 优先级，主(100) > 备(90)
    advert_int 1               # 每秒喊话一次

    virtual_ipaddress {
        192.168.1.100          # ★ 这就是浮动 VIP
    }
}
```
**lb2（备）**：同样装 keepalived，配置只在三处不同：
```conf
    state BACKUP
    priority 90
    # virtual_router_id、interface、virtual_ipaddress 与主一致
```
```bash
sudo systemctl restart keepalived    # 两台都重启
```

### 6.4.2 验证
```bash
# 在 lb1 上：
ip addr | grep 192.168.1.100
# 能看到 VIP 挂在 lb1 的网卡上

# 随便找第三台机器（或 web1）：
curl http://192.168.1.100           # 通过 VIP 访问 → 分流到 web1/web2
```
### 6.4.3 见证第二个奇迹：主调度员"猝死"
```bash
# 在 lb1 上直接关机（或停服务）：
sudo systemctl stop keepalived
# 到 lb2 上看：
ip addr | grep 192.168.1.100        # VIP 竟然跑到 lb2 上了！
# 再访问 VIP：
curl http://192.168.1.100           # 照常工作！
```
**你把"单点故障"消灭了。** 现在这套架构里挂任何一台机器，网站都能活。

### 6.4.4 完整架构图（画在纸上，你会为它骄傲）
```
         用户
          │
          ▼
     VIP: 192.168.1.100   ← 浮动IP（谁活着谁持有）
      ┌───┴───┐
      │       │
    lb1      lb2          ← HAProxy 双机（主备）
   (MASTER) (BACKUP)
      │       │
      └───┬───┘
          │ 分流（roundrobin + 健康检查）
      ┌───┴───┐
      │       │
    web1     web2         ← 后端服务器（挂了自动剔除）
```

## 6.5 排错指南（HAProxy/Keepalived 高频 5 坑）

1. **HAProxy 起不来**：`sudo haproxy -c -f /etc/haproxy/haproxy.cfg` 检查配置语法（和 nginx -t 一个道理）。
2. **访问 VIP 不通**：① keepalived 写错网卡名（用 `ip addr` 核对）② 两台 virtual_router_id 不一致 ③ 防火墙拦了 VRRP（组播协议 112）。
3. **流量全给一台**：另一台 `check` 失败被踢了。在 stats 面板看状态，去那台上 `curl localhost` 自查。
4. **两台都抢当主（VIP 乱跳）**：priority 设成一样了，或网卡名错。
5. **改了配置没生效**：`sudo systemctl restart haproxy`（HAProxy 改配置必须重启，它不像 nginx 支持 reload 那么丝滑——不过新版本也支持 `-sf` 平滑重启）。
