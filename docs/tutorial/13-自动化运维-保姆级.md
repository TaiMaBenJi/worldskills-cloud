## 13.2 Ansible 实战

### 13.2.1 核心概念（三个词起步）
| 词 | 是什么 | 比喻 |
|----|--------|------|
| **inventory** | 被管理机器的清单 | 员工花名册 |
| **playbook** | 一份"要做什么"的剧本（YAML） | 给员工的任务书 |
| **module** | 干具体活的工具箱（apt、copy、service…） | 各种工具 |

**特点：无 Agent**——不用在目标机器装任何东西，靠 SSH 就能管（这也是它火的原因）。

### 13.2.2 安装与第一次战斗
```bash
sudo apt install -y ansible
ansible --version

# 准备一个"花名册"（先用本机练）
mkdir -p ~/ansible-lab && cd ~/ansible-lab
nano inventory.ini
```
```ini
[web]
localhost ansible_connection=local     # 本机练手（真实场景写对方 IP）

[web:vars]
ansible_user=student
```
**第一次"ping"（不是网络 ping，是"Ansible 能不能连上你"的握手）**：
```bash
ansible -i inventory.ini web -m ping
# → localhost | SUCCESS => {"changed": false, "ping": "pong"}
```
`SUCCESS` = 连上了。**世界赛 Module A 的 A15-01 评分点就是"ansible ping 通过"——你已经完成了一个评分点。**

### 13.2.3 Playbook：把操作写成剧本
```bash
nano site.yml
```
```yaml
---
- name: 配置 Web 服务器          # 剧本名（给人看的）
  hosts: web                     # 对花名册里的哪组机器执行
  become: true                   # 相当于 sudo（提权）
  tasks:                         # 任务列表（从上到下执行）

    - name: 安装 nginx           # 每个任务有 name（执行时打印出来）
      apt:
        name: nginx
        state: present           # present=安装 latest=装最新版

    - name: 部署首页
      copy:
        content: "<h1>Ansible 部署的页面</h1>\n"
        dest: /var/www/html/index.html

    - name: 确保 nginx 运行并自启
      service:
        name: nginx
        state: started
        enabled: true

    - name: 防火墙放行 80
      ufw:
        rule: allow
        port: "80"
```
运行：
```bash
ansible-playbook -i inventory.ini site.yml
```
输出每一行 `TASK [...]` 就是执行过程，最后有统计：
```
PLAY RECAP
localhost : ok=4 changed=3 unreachable=0 failed=0
```
**ok=检查了 4 项，changed=真正改变了 3 项，failed=0。**

**再运行一次**——注意！changed 变成 0 了：
```bash
ansible-playbook -i inventory.ini site.yml
# changed=0, ok=4
```
**这就是"幂等性"（Idempotent）**：同一个剧本跑一万遍，结果都一样，不会重复装错。**这是配置管理的灵魂——写"目标状态"而不是"操作步骤"。**（对应：世界赛 A15 的第二次运行不应该有变化。）

### 13.2.4 变量与模板（让剧本通用化）
```bash
mkdir -p group_vars
nano group_vars/web.yml
```
```yaml
site_title: "我的公司网站"
site_port: 80
```
用模板文件（`templates/index.html.j2`）：
```html
<h1>{{ site_title }}</h1>
<p>服务端口: {{ site_port }}</p>
```
剧本里：
```yaml
    - name: 用模板部署首页
      template:
        src: templates/index.html.j2
        dest: /var/www/html/index.html
```
`{{ 变量 }}` 会被替换。**这就是"一套剧本，多环境复用"的秘密。**

### 13.2.5 批量管理多台机器（真正的用武之地）
在真实场景（比如第 12 章的 EC2 集群）：
```ini
[web]
10.0.1.10
10.0.1.11
10.0.2.10

[db]
10.0.11.10
```
```bash
ansible -i inventory.ini all -m ping          # 一次 ping 所有机器
ansible-playbook -i inventory.ini site.yml    # 一次配置全部 web
```
**一条命令，三台服务器同时装好 nginx——这就是自动化的威力。**

## 13.3 Terraform 实战

### 13.3.1 核心概念（四个词）
| 词 | 是什么 |
|----|--------|
| **provider** | 对接哪个平台（aws/azurerm/google…） |
| **resource** | 要创建的资源（"我要一台 EC2"） |
| **state** | 记录"已经建了什么"的账本（重要！） |
| **plan/apply** | 先看"要变什么"，再执行 |

**核心思想：把云资源写成代码（IaC，Infrastructure as Code）**。好处：可版本管理、可复用、可 review、可一键重建。

### 13.3.2 安装与第一个项目
```bash
# Ubuntu 安装（用官方源）
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install -y terraform
terraform -version
```
```bash
mkdir -p ~/tf-lab/s3 && cd ~/tf-lab/s3
nano main.tf
```
```hcl
# ① 声明用 AWS provider
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "us-west-2"        # 换成你的区域
}

# ② 定义一个资源：S3 桶
resource "aws_s3_bucket" "demo" {
  bucket = "my-tf-demo-2026-xyz123"   # 全球唯一名字（加上你的随机后缀）
  tags = {
    Name    = "terraform-demo"
    Owner   = "student"
  }
}
```
**工作流四步走（背下来）**：
```bash
terraform init      # ① 初始化：下载 provider 插件（第一次必做）
terraform plan      # ② 预演：显示"将创建 1 个资源"（绿色 + 号）
terraform apply     # ③ 执行：输入 yes 确认 → 创建！
terraform destroy   # ④ 销毁：练习完删掉（省钱）
```
**看 plan 的输出**——它会逐条列出"哪些要建（+）、要改（~）、要删（-）"。**养成"先 plan 再 apply"的铁律**（就像"先 nginx -t 再 reload"）。

### 13.3.3 完整的 EC2 + 安全组示例
```hcl
resource "aws_security_group" "web" {
  name        = "web-sg"
  description = "allow http and ssh"

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]     # 学习期；生产建议只放你的 IP/32
  }
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "web" {
  ami                    = "ami-xxxxxxxx"    # 换成你区域里的 Ubuntu AMI ID
  instance_type          = "t3.micro"
  key_name               = "mykey"
  vpc_security_group_ids = [aws_security_group.web.id]

  user_data = <<-EOF
    #!/bin/bash
    apt update && apt install -y nginx
    echo "Hello from Terraform" > /var/www/html/index.html
  EOF

  tags = { Name = "tf-web" }
}

output "public_ip" {                 # 输出公网 IP（apply 后显示）
  value = aws_instance.web.public_ip
}
```
```bash
terraform apply          # 全自动：建安全组 → 建 EC2 → 装 nginx
# output 里给你 IP → 浏览器访问 → Hello from Terraform
terraform destroy        # 全部清理（资源名字都记在 state 里，删得干干净净）
```

### 13.3.4 变量、模块、远程状态（工程化三件套）
**变量（variables.tf）**：
```hcl
variable "region" {
  default = "us-west-2"
}
variable "instance_type" {
  default = "t3.micro"
}
```
使用：`instance_type = var.instance_type`；命令行覆盖：`terraform apply -var="instance_type=t3.small"`。

**模块（modules/）**：把一堆资源打包成可复用的"乐高块"：
```hcl
module "web_cluster" {
  source        = "./modules/web"
  instance_count = 3
}
```
韩国赛题解里 `modules/bastion`、`modules/vpc` 就是这个结构。

**远程状态（团队必需）**：state 默认存在本地文件，多人协作会打架。生产放 S3：
```hcl
terraform {
  backend "s3" {
    bucket = "my-tf-state-bucket"
    key    = "prod/terraform.tfstate"
    region = "us-west-2"
  }
}
```

### 13.3.5 一些救命命令
```bash
terraform fmt               # 格式化代码（对齐缩进，提交前跑）
terraform validate          # 语法检查
terraform state list        # 看当前管理了哪些资源
terraform output            # 看输出值
terraform plan -destroy     # 预览"销毁会删什么"
```

## 13.4 CI/CD 初见：让代码"自动上线"

**CI（持续集成）**= 代码一提交，自动测试/构建；**CD（持续部署）**= 构建产物自动发布到服务器。

### 13.4.1 用 GitHub Actions 写第一条流水线
仓库里建 `.github/workflows/deploy.yml`：
```yaml
name: Deploy Site
on:
  push:
    branches: [main]          # 一推到 main 分支就触发

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: 部署到服务器
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_IP }}        # 在仓库 Secrets 里配置
          username: ubuntu
          key: ${{ secrets.SSH_KEY }}
          script: |
            cd /var/www/mysite
            git pull
            sudo systemctl reload nginx
```
**流程**：你 push 代码 → GitHub 的机器自动 SSH 到你的服务器 → 拉取新代码 → 重载服务。**一句话：点一下提交，网站自动更新。**

### 13.4.2 与比赛的关系
- 韩国赛：`make images`（构建镜像 → 推 ECR → 部署）就是 CI/CD 的本地版；进阶题直接用 GitHub Actions/CodePipeline
- 世界赛：Ansible 自动配置（A15）+ 各类脚本化部署
- **记住分层**：CI 管"构建产物"，CD/GitOps 管"部署到位"（第 14 章会提 GitOps 的 ArgoCD）

## 13.5 综合实战：一条龙"从零建站"

**用 Terraform + Ansible 完整交付：**
```bash
# 1. Terraform：建 VPC + 2 台 EC2 + 安全组
cd ~/tf-lab/full && terraform apply
# 2. 生成 Ansible 花名册（把输出的 IP 填进去）
terraform output -json > hosts.json
# 3. Ansible：对两台机器一键配置
ansible-playbook -i inventory.ini site.yml
# 4. 验证：curl 两台机器的 IP，都是配置好的页面
# 5. 销毁
terraform destroy
```
**恭喜——你已经完成了现代运维的完整闭环：代码建资源 → 代码配机器 → 验证 → 销毁。** 这就是 IaC 的全部哲学。
