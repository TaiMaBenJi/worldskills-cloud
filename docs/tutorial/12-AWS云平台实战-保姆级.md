# 第 12 章 · AWS 云平台实战（从零到一架完整架构）

> 前面 11 章都在你自己的机器上折腾。本章开始，我们**到真云上去**。

## 12.1 开账号与认识控制台

### 12.1.1 注册
1. 打开 `aws.amazon.com` → 创建账户（需要：邮箱 + 信用卡/银联卡 + 手机号）
2. 区域选择：**建议注册海外区（如美国俄勒冈 us-west-2）**——国际版功能全（比赛同款），国内区（宁夏/北京）由光环新网运营，功能略不同
3. 注册后第一次登录就是"根用户（root）"——**这个账号是"上帝账号"，永远不要日常使用它**（马上往下看为什么）

### 12.1.2 先设两个保命符（注册完立刻做！）
**① 根用户开 MFA（双因素认证）**：
右上角账号名 → Security credentials → Assign MFA device → 手机装个验证器 App（如 Google Authenticator）扫码绑定。

**② 设置预算警报（防止一夜扣费几百刀）**：
搜索栏搜 **Budgets** → 创建预算 → 每月成本预算 $10 → 设 50%（$5）时邮件报警。
> **新手保护机制：预算警报是你最重要的安全网。** 记住：云上"忘记删的资源"会一直花钱（尤其是 EC2、RDS、NAT 网关）。

## 12.2 IAM：给"人"和"程序"发工牌

**核心思想：永远不用根账号干活，按需创建子用户/角色。**

### 12.2.1 创建一个管理员子用户（给自己用）
1. 搜索 **IAM** → 用户 → 创建用户
2. 名字：`admin-me`，勾选"提供控制台访问"，设密码
3. 权限：勾选"直接附加策略" → 选 `AdministratorAccess`（学习期先全权；生产要最小权限）
4. 创建完成 → **用这个新用户重新登录控制台**

### 12.2.2 核心概念三板斧
| 概念 | 是什么 | 比喻 |
|------|--------|------|
| **用户（User）** | 一个人/一个程序的账号 | 员工的工牌 |
| **策略（Policy）** | 一份 JSON 权限清单 | 工牌的开门范围 |
| **角色（Role）** | 可以被"借用"的身份 | 临时通行证（EC2/K8s 用它访问别的服务） |

**策略长这样（JSON）：**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::my-bucket/*"
    }
  ]
}
```
读法："允许 对 my-bucket 下的对象 执行 读取和上传 操作"。**最小权限原则**：只给需要的动作。

### 12.2.3 访问密钥（给程序用的"用户名密码"）
命令行工具（aws cli / Terraform）需要密钥：IAM → 用户 → 安全凭证 → 创建访问密钥。
```bash
# 在 Linux 上装 AWS CLI
sudo apt install -y awscli
aws configure
# 依次输入: Access Key / Secret Key / region (如 us-west-2) / output (json)
aws sts get-caller-identity    # 验证：显示你的账号信息 = 配好了
```
⚠️ **密钥 = 你的银行卡号+密码**。绝不提交到 GitHub、绝不发给别人。（实践中推荐用 SSO/角色而不是长期密钥，学习期先这样。）

## 12.3 VPC：在云上圈一块地（最重要的一节）

**VPC（Virtual Private Cloud）= 你在 AWS 里私有的"虚拟机房"**。所有资源（服务器、数据库）都住在这个机房里。

### 12.3.1 三个核心概念
- **子网（Subnet）**：机房里的"房间"。分**公有子网**（能通互联网，放对外服务）和**私有子网**（不通互联网，放数据库等宝贝）——**公有/私有分离是安全设计的起点**。
- **路由表（Route Table）**：房间门口的"路牌"——去互联网走哪条路、去别的子网走哪条路。
- **网关**：通往互联网的大门。**IGW**（Internet Gateway，正常大门）；**NAT Gateway**（让私有子网的机器"单向外访"后门——可以出去下载更新，但外面进不来）。

### 12.3.2 手把手建一套 VPC（控制台操作，逐屏对照）
1. 搜索 **VPC** → 创建 VPC
2. 名称 `my-vpc`，IPv4 网段 `10.0.0.0/16`（能容纳 6 万多个 IP，"小区"够大）
3. 顺便建子网（勾选）：
   - 公有子网 ×2：`10.0.1.0/24`（可用区 A）、`10.0.2.0/24`（可用区 B）
   - 私有子网 ×2：`10.0.11.0/24`、`10.0.12.0/24`
4. 创建 IGW 并绑定到 VPC
5. **给公有子网的路由表**加一条：`0.0.0.0/0 → IGW`（"去互联网都走大门"）
6. （进阶）建 NAT 网关放在公有子网，给私有子网路由 `0.0.0.0/0 → NAT`

**为什么两个可用区？** 可用区 ≈ 物理上分开的机房。一个机房停电，另一个还在——**这就是云上的"高可用"**。世界赛架构题第一要求就是"多可用区部署"。

**验证理解**：画一张图（VPC 里 4 个子网、各自的出口），能从记忆里画出来，这节才算学会。

## 12.4 EC2：启动你的云服务器

### 12.4.1 启动第一台（逐屏手把手）
1. 搜索 **EC2** → 启动实例
2. 名称 `my-first-server`
3. 镜像（AMI）：**Ubuntu Server 22.04 LTS**
4. 实例类型：`t2.micro`（免费额度机型）
5. **密钥对**：创建新密钥对 `mykey` → 下载 `.pem` 文件（**丢了就永远连不上这台机器**，好好保管）
6. **网络设置**：选你刚建的 VPC、公有子网；安全组勾选"允许 SSH"（22 端口）
7. 存储：默认 8GB gp3
8. 启动！等 1 分钟 → 状态"运行中"

### 12.4.2 连上去
```bash
# ① 修权限（.pem 必须只有你能读，否则 ssh 拒绝）
chmod 400 ~/Downloads/mykey.pem

# ② 连接（IP 在控制台能拿到——"公有 IPv4 地址"）
ssh -i ~/Downloads/mykey.pem ubuntu@<公网IP>
# → 你就登录到云端的服务器了！和本地虚拟机一模一样地用
```
**从这一刻起，第 1-9 章学的一切都可以在云上用了。** 试试：
```bash
sudo apt update && sudo apt install -y nginx
# 然后在控制台：安全组 → 入站规则 → 允许 HTTP 80 端口
# 浏览器访问 http://<公网IP> → Welcome to nginx!
```
（回忆第 2 章："云安全组 + 服务器防火墙"两道门。这道题你做过 N 遍了。）

### 12.4.3 省钱要点（新手最容易烧钱的地方）
- 不用了就 **stop**（停止），不要留着跑（停止后不收计算费，但硬盘/弹性 IP 仍可能小计费）
- **彻底不用就 terminate（终止）**——但注意：终止=连硬盘一起销毁，不可恢复
- 免费额度：每月 750 小时 t2.micro/t3.micro（够一台机器整月）

## 12.5 S3：无限大的网盘（对象存储）

**S3 = 存文件的超级网盘**（照片、备份、静态网站、大数据都能放），容量无限，按量付费。

### 12.5.1 动手指南
```bash
# 命令行操作（比控制台点更快）
aws s3 ls                          # 列出你的桶（bucket）
aws s3 mb s3://my-bucket-唯一名字   # 建桶（名字全球唯一！）
aws s3 cp 本地文件.txt s3://my-bucket-唯一名字/    # 上传
aws s3 ls s3://my-bucket-唯一名字/                 # 查看
aws s3 sync ~/photos s3://my-bucket-唯一名字/photos/   # 整个目录同步（增量上传）★
aws s3 cp s3://my-bucket-唯一名字/文件.txt ./       # 下载
aws s3 rm s3://my-bucket-唯一名字/文件.txt          # 删除
```

### 12.5.2 三个"比赛常用"场景
1. **静态网站托管**：桶属性开"静态网站托管"，上传 index.html，浏览器直接访问（便宜到几乎免费）
2. **备份目标**：`aws s3 sync /backup s3://桶/backup/`（配 crontab = 自动云备份）
3. **事件驱动**：上传文件触发 Lambda（韩国赛题的核心模式！第 13 章展开）

### 12.5.3 权限与安全
- 默认全私有（好！）；要给外部访问用**桶策略**或**预签名 URL**（定时临时链接）
- 门禁细节：IAM 策略（谁能操作桶）+ 桶策略（桶自己声明谁能进）+ 加密（SSE-S3/KMS）

## 12.6 RDS：让云托管你的数据库

手动装 MySQL（第 3 章）还要自己备份、打补丁、扩容、容灾。**RDS = 托管的数据库**：这些烦人事 AWS 全包。

### 12.6.1 建一个
1. 搜索 **RDS** → 创建数据库 → MySQL
2. 模板选"免费套餐"→ 实例 `db.t3.micro`
3. **多可用区部署**：生产选"是"（备库同步，主挂了自动切换）；学习选"否"省钱
4. 网络：选你的 VPC + **私有子网**（数据库永远不放公有子网）
5. 安全组：只允许来自"应用服务器安全组"的 3306——**不要对 0.0.0.0/0 开放！**
6. 设置主密码 → 创建（等几分钟）

### 12.6.2 连上它
```bash
sudo apt install -y mysql-client
mysql -h <RDS端点地址> -u admin -p
```
（端点地址在 RDS 控制台"连接和安全性"里，形如 `xxx.us-west-2.rds.amazonaws.com`）

### 12.6.3 RDS 的价值（比赛视角）
- 自动备份（时间点恢复）、自动补丁、一键加只读副本（读扩展）、多可用区故障自动切换
- **考点**：题目常说"数据库必须多可用区+只读副本+自动备份"——就是创建时勾选项

## 12.7 负载均衡 + 自动伸缩（云上的第 6 章升级版）

**ELB（负载均衡器）+ ASG（Auto Scaling Group，自动伸缩组）** = 你第 6 章手搓的"负载均衡+多台机器"，全部托管化。

### 12.7.1 概念对照（你学过的 vs 云上的）
| 你手搓的 | AWS 托管 |
|----------|----------|
| HAProxy | ALB（应用负载均衡）/ NLB（网络负载均衡） |
| keepalived VIP | ELB 自带（多可用区节点） |
| 多台 web 服务器 | ASG（按规则自动增减 EC2） |
| 健康检查 check | 目标组健康检查 |
| 手动加机器 | 伸缩策略（CPU>70% 加一台） |

### 12.7.2 搭一套（核心操作）
1. **建启动模板**（Launch Template）：定义"新人"的规格（AMI、机型、密钥、安全组、用户数据）
   - 用户数据（User data）里可以直接写安装脚本：
     ```bash
     #!/bin/bash
     apt update && apt install -y nginx
     echo "Hello from $(hostname)" > /var/www/html/index.html
     ```
2. **建 ALB**：选两个公有子网 → 建目标组（Target Group，健康检查路径 `/`）
3. **建 ASG**：挂刚建的模板 → 选两个公有子网 → 期望容量 2，最小 1，最大 4 → 挂到 ALB 目标组
4. **配伸缩策略**：目标跟踪 → CPU 利用率 70%
5. 访问 ALB 的 DNS 名称 → 看到页面！**刷新几次，看到不同主机名** = 负载均衡 OK。
6. 压测触发扩容（装 `stress` 或 `ab`），观察 ASG 自动加机器（Activity 历史里能看到）

**这套东西 = 葡萄牙赛题的核心（ASG + step scaling + NLB）**。做完这个实验，你已经能看懂一半的真题架构。

## 12.8 CloudWatch：监控你的云

```bash
# 常用操作（也能控制台点点点）
aws cloudwatch list-metrics --namespace AWS/EC2 | head
# 看某台机器 CPU：
aws cloudwatch get-metric-statistics --namespace AWS/EC2 \
  --metric-name CPUUtilization --dimensions Name=InstanceId,Value=<实例ID> \
  --start-time $(date -d '1 hour ago' +%FT%TZ) --end-time $(date +%FT%TZ) \
  --period 300 --statistics Average
```
- **告警**：CloudWatch → 告警 → 创建（如 CPU > 80% 发邮件）——比赛里"高可用与监控"评分点的同款
- **日志**：装 CloudWatch Agent 把应用日志送上云（韩国 2026 题考点）
- 记住三个词：**指标（Metrics）→ 告警（Alarms）→ 日志（Logs）**

## 12.9 综合项目：在云上复刻你的"个人小站"（毕业设计）

**要求**（把前面所有章节的能力搬到云上）：
1. VPC：2 公有子网 + 2 私有子网，跨两个可用区
2. EC2：一台 Web 服务器在公有子网，跑你的网站（用 user data 自动安装）
3. S3：静态资源放 S3；开启备份同步
4. RDS：MySQL 在私有子网，只允许 Web 服务器访问
5. ALB + ASG：两台 EC2 起步，挂负载均衡，配 CPU 70% 伸缩
6. CloudWatch：CPU 告警 + RDS 连接数告警
7. IAM：给 EC2 挂"只能读写自己 S3 桶"的角色（不要用密钥）
8. 预算：$10 告警开着
9. **验收**：浏览器访问 ALB 地址循环看到两台机器的响应；压测触发扩容；停止一台 EC2 看 ALB 自动摘除
10. **删除所有资源**（terraform destroy 或手动清理），确认账单回零

**做完这个项目，你就拥有了"云架构师初级"的实操能力——这已经是世赛题目的入门水平。**
