> **编译原理 = 把"人话"翻译成"机器话"的全部学问。**

## 19.1 编译原理到底学什么

### 19.1.1 一个类比先看懂全部

你写的是：`x = 10; print(x * 2 + 5);`

CPU 只认识：一卡车"把内存第 7 号格的数搬到寄存器"这样的指令。

**中间的翻译官，就是编译器。** 编译原理研究的，就是怎么把这件事做得**又快又对**：

- 怎么读懂"人话"？（词法、语法分析）
- 怎么确认"话说得有道理"？（语义分析）
- 怎么翻译得又快又省？（中间代码、优化）
- 怎么落到目标机器？（代码生成）

### 19.1.2 为什么值得学（不只为写编译器）

| 你以后做 | 编译原理给你的 |
|---|---|
| 写业务代码 | 理解语言特性（闭包、泛型、元编程）为什么这样设计 |
| 调性能 | 看懂 `-O2` 做了什么、为什么这里慢 |
| 做架构 | 解析器思维=把任何文本变成结构（JSON/DSL/日志分析到处是） |
| 学安全 | 注入、反序列化漏洞本质就是"翻译边界没把好" |
| 面试 | JIT、GC、AOT、静态分析是高频话题 |
| 造轮子 | 想写语言/DSL/代码生成器？这就是入场券 |

### 19.1.3 三条翻译路线（先分清概念）

| 路线 | 代表 | 过程 | 特点 |
|---|---|---|---|
| **编译型** | C / Rust / Go | 源码 → 机器码，直接执行 | 快，但要先编译 |
| **解释型** | Python / (早期)JS | 源码 → 边解释边执行 | 灵活，但慢 |
| **混合型** | Java / C# / 现代JS | 源码 → 字节码 → JIT 编译执行 | 平衡，现代主流 |

> 现代世界的真相：界限早已模糊。V8 会把热点 JS 直接编译成机器码；Python 也有 PyPy JIT；C# 可以 AOT。**理解中间层，才能理解现代语言。**

## 19.2 全景图：编译器的七个阶段

```
源码 "x = 10;"
  │
  ▼
① 词法分析 Lexer     →  切成 token 流（id:x, =, num:10, ;）
  │
  ▼
② 语法分析 Parser    →  组装成 AST（语法树）
  │
  ▼
③ 语义分析           →  查符号表、查类型（x 声明过吗？类型对吗？）
  │
  ▼
④ 中间代码 IR        →  三地址码/字节码（与机器无关的形态）
  │
  ▼
⑤ 优化               →  常量折叠、死代码消除、内联…
  │
  ▼
⑥ 目标代码生成       →  机器码 / 汇编 / 字节码
  │
  ▼
⑦ 链接（可执行文件）  →  与库合并，产出程序
      [ 符号表 + 错误处理 全程伴随 ]
```

**一句话记忆**：**词、句、义、中、优、码、链**——前四个阶段叫"前端"（跟语言相关），后面叫"后端"（跟机器相关）。这也是为什么 LLVM 能让 C/C++/Rust/Swift 共享同一套优化器：**前端千差万别，后端殊途同归**。

## 19.3 词法分析：把字符流切成"词"

**任务**：纯字符 → 有意义的 token。规则就是"模式匹配"。

| 词素 | token 类型 | 说明 |
|---|---|---|
| `x` `print` | 标识符/关键字 | 字母开头的字母数字串 |
| `10` `3.14` | 数字字面量 | 位数/小数点 |
| `+` `*` `==` | 运算符 | **最长匹配**（`=` 和 `==` 分得清） |
| 空格/换行 | 忽略 | 但行号要记（报错用） |

**理论核心**：每种 token 用**正则表达式**描述 → 正则可以转成**有限自动机（DFA）** → DFA 就是"读一个字符走一步"的状态机。

**为什么要学自动机而不是随便写？** 因为工具（flex/lex）把"正则 → DFA"全自动化了：你写规则，它生成代码。这就是很多"编程语言课设"里"用 flex 做词法"的由来。

---

## 19.4 语法分析：把"词"拼成"句"

**任务**：token 流 → 语法树（AST）。规则是**文法**（上下文无关文法 CFG）。

```
表达式文法：
  expr  → expr + term | term        （表达式是 加法 或 单项）
  term  → term * factor | factor     （单项是 乘法 或 因子）
  factor → number | ( expr )        （因子是 数字 或 括号表达式）
```

**优先级、结合性怎么体现？** 关键就在文法的**层次**：乘法的规则"更深一层"，所以它先算。`2 + 3 * 4` 的树自然长成 `2 + (3*4)`。

**两大流派**：

| 流派 | 方法 | 特点 | 谁在用 |
|---|---|---|---|
| **自顶向下** | 递归下降 | 好写、好懂、好报错 | 手写解析器（大多数实用编译器） |
| **自底向上** | LR 分析 | 理论漂亮、能处理的文法广 | yacc/bison（生成器） |

考试的重头戏（FIRST/FOLLOW 集、LR 分析表）就在这一节——**先建立起"它们只是两种自动拼句的方法"的直觉，再去死磕表格的计算，就不容易晕**。

**递归下降的核心写法**（记住这个套路，实战最有用）：每个文法规则写成一个函数，函数内部看到什么 token 就调什么函数。

---

## 19.5 语义分析：确认"话有道理"

语法只保证"结构合法"，语义要保证"意思成立"：

- `x = y + 1;` 里 **y 声明过吗？**（符号表查询）
- `"hello" + 1` **类型对吗？**（类型检查）
- 变量作用域（局部/全局）、重复定义、函数调用参数数量……

**符号表**是语义分析的主战场：一个"名字 → 类型/位置/作用域"的登记本，用栈结构管理作用域进出（进入代码块 push，离开 pop）。

> 一句话：**语法 = 造句法（主谓宾对不对），语义 = 语义学（这句话有没有意义）。** "绿色的梦在抱怨"——语法对，语义不通。

## 19.6 中间表示与代码生成

直接从前端生成机器码？太笨——每种语言×每种机器=重写一遍。
正解：先降到**中间表示（IR）**：

| IR 形态 | 样子 | 用在哪 |
|---|---|---|
| AST 直接走 | 树遍历求值 | 解释器 |
| 三地址码 | `t1 = a + b` | 优化/教学/编译器后端 |
| 字节码 | `LOAD a; LOAD b; ADD` | JVM、CPython、.NET |
| SSA | 每个变量只赋值一次 | LLVM、现代优化 |

**例子**：`z = (x + y) * -2;` 的字节码——

```
LOAD x     把 x 压栈
LOAD y     把 y 压栈
ADD        弹出两个相加，结果压栈
PUSH 2     把 2 压栈
NEG        取负
MUL        相乘
STORE z    弹出结果存进 z
```

**看懂了吗**：编译 =把树"拉直"成一串命令；运行 =一台"栈机器"按命令走。本章 19.8 节你会亲手实现这套东西。

## 19.7 优化入门：为什么 `-O2` 能快一倍

| 优化 | 做了什么 | 例子 |
|---|---|---|
| 常量折叠 | 编译期算好常数 | `2*3+1` → `7` |
| 常量传播 | 常量带入 | `x=5; y=x+1;` → `y=6` |
| 死代码消除 | 删永远走不到/没用的代码 | `if(1){A}else{B}` → 只留 A |
| 公共子表达式 | 重复计算只算一次 | `a*b` 出现 3 次 → 算 1 次 |
| 内联 | 函数体展开 | 小函数直接铺开 |
| 循环不变量外提 | 循环里不变的搬到外面 | `for(i..){ y = k*2+1 }` |

> 优化要**保证语义不变**——这就是为什么它难：既要激进（快），又要保守（对）。安全领域的"编译器级对抗"（比如某些壳利用优化行为藏代码）也源自这里。

## 19.8 动手：亲手写一个完整的 mini 编译器（已实测）

> 下面这套代码实现了**一个完整的小语言编译器**：词法 → 语法 → ①直接解释 ②编译成字节码并用虚拟机执行。**每个部分我都实跑验证过**，你可以直接复制到电脑上运行（存成 mini_lang.py，`python3 mini_lang.py`）。

**我们的玩具语言长这样**：

```
x = 10;
y = x * 2 + 5;
print(y);
if (y > 20) { print(y - 100); } else { print(0); }
z = (x + y) * -2;
print(z);
```

### 19.8.1 ① 词法分析（约 20 行）

```python
import re
TOKEN_RE = re.compile(r"""
    (?P<num>\d+)
  | (?P<id>[A-Za-z_]\w*)
  | (?P<op>==|<=|>=|[-+*/(){};=<>])
  | (?P<ws>\s+)
""", re.X)

def tokenize(src):
    tokens, pos = [], 0
    while pos < len(src):
        m = TOKEN_RE.match(src, pos)
        if not m:
            raise SyntaxError("无法识别的字符: %r" % src[pos])
        pos = m.end()
        if m.lastgroup == "ws":
            continue
        tokens.append((m.lastgroup, m.group()))
    tokens.append(("eof", ""))
    return tokens
```

实际效果（真实运行输出）：

```
x = 10;  →  [('id','x'), ('op','='), ('num','10'), ('op',';') ...]
```

### 19.8.2 ② 语法分析：递归下降 → AST（核心骨架）

文法先写清楚（这一步叫"设计语言"）：

```
program := stmt*
stmt    := ident '=' expr ';' | 'print' '(' expr ')' ';'
         | 'if' '(' expr ')' block ('else' block)?
expr    := add (('<'|'>'|'<='|'>='|'==') add)?
add     := mul (('+'|'-') mul)*
mul     := unary (('*'|'/') unary)*
unary   := '-' unary | primary
primary := num | ident | '(' expr ')'
```

然后"每个规则一个函数"：

```python
class Parser:
    def __init__(self, toks): self.toks, self.i = toks, 0
    def peek(self): return self.toks[self.i]
    def next(self):
        t = self.toks[self.i]; self.i += 1; return t
    def expect(self, val):
        t = self.next()
        if t[1] != val: raise SyntaxError("期望 %r 得到 %r" % (val, t[1]))
        return t

    def stmt(self):
        t = self.peek()
        if t[1] == "print":
            self.next(); self.expect("("); e = self.expr(); self.expect(")"); self.expect(";")
            return ("print", e)
        if t[1] == "if":
            self.next(); self.expect("("); c = self.expr(); self.expect(")")
            th = self.block()
            el = None
            if self.peek()[1] == "else":
                self.next(); el = self.block()
            return ("if", c, th, el)
        if t[0] == "id":
            name = self.next()[1]; self.expect("="); e = self.expr(); self.expect(";")
            return ("assign", name, e)
        raise SyntaxError("不认识的语句: %r" % (t,))

    def add(self):
        node = self.mul()
        while self.peek()[1] in ("+", "-"):
            op = self.next()[1]
            node = ("bin", op, node, self.mul())
        return node
    # mul / unary / primary 同理（完整版见文末清单文件）
```

真实运行效果：

```
y = x * 2 + 5;
→ ('assign', 'y', ('bin','+', ('bin','*', ('var','x'), ('num',2)), ('num',5)))
```

**看到了吗**：优先级在树里自动分好了——`+` 在顶层，`*` 是它的左孩子。

### 19.8.3 ③ 方式一：直接解释执行（树遍历）

```python
def evaluate(node, env):
    k = node[0]
    if k == "num": return node[1]
    if k == "var": return env.get(node[1], 0)
    if k == "neg": return -evaluate(node[1], env)
    if k == "bin":
        a, b = evaluate(node[2], env), evaluate(node[3], env)
        op = node[1]
        if op == "+": return a + b
        if op == "-": return a - b
        if op == "*": return a * b
        if op == "/": return a // b if b else 0
        if op == ">": return 1 if a > b else 0
        # ...其余比较同理
```

**这就是"解释器"的本质**：顺着树跑，算到哪算到哪。

### 19.8.4 ④ 方式二：编译成字节码 + 虚拟机执行（升华部分）

编译器：树 → 直线指令流。**if 的编译要"回填跳转地址"**（先占位、后填真地址）：

```python
def compile_node(node, code):
    k = node[0]
    if k == "num": code.append(("PUSH", node[1]))
    elif k == "var": code.append(("LOAD", node[1]))
    elif k == "neg": compile_node(node[1], code); code.append(("NEG",))
    elif k == "bin":
        compile_node(node[2], code); compile_node(node[3], code)
        code.append((BINOPS[node[1]],))   # + → ADD 等

def compile_stmts(stmts, code):
    for s in stmts:
        if s[0] == "assign": compile_node(s[2], code); code.append(("STORE", s[1]))
        elif s[0] == "print": compile_node(s[1], code); code.append(("PRINT",))
        elif s[0] == "if":
            compile_node(s[1], code)
            jz = len(code); code.append(("JZ", None))   # 先占位
            compile_stmts(s[2], code)
            if s[3]:
                jmp = len(code); code.append(("JMP", None))
                code[jz] = ("JZ", len(code))            # 回填：条件假→跳去 else
                compile_stmts(s[3], code)
                code[jmp] = ("JMP", len(code))          # 回填：then 完→跳过 else
            else:
                code[jz] = ("JZ", len(code))
```

虚拟机：一个数组当"栈"，一个指针当"程序计数器"：

```python
def vm_run(code, env=None, out=None):
    env, out, stack, pc = env or {}, out or [], [], 0
    while pc < len(code):
        ins = code[pc]; pc += 1
        op = ins[0]
        if op == "PUSH": stack.append(ins[1])
        elif op == "LOAD": stack.append(env.get(ins[1], 0))
        elif op == "STORE": env[ins[1]] = stack.pop()
        elif op == "ADD": b, a = stack.pop(), stack.pop(); stack.append(a + b)
        elif op == "MUL": b, a = stack.pop(), stack.pop(); stack.append(a * b)
        elif op == "JZ":
            if stack.pop() == 0: pc = ins[1]
        elif op == "JMP": pc = ins[1]
        elif op == "PRINT": out.append(stack.pop())
        elif op == "HALT": break
    return out
```

  01  ('STORE', 'x')    09  ('PRINT',)         14  ('LOAD', 'y')
  02  ('LOAD', 'x')     10  ('LOAD', 'y')      16  ('SUB',)
  03  ('PUSH', 2)       11  ('PUSH', 20)       17  ('PRINT',)

  05  ('PUSH', 5)       19  ('PUSH', 0)  ...   21  ('LOAD', 'x') ...

## 19.9 从玩具到工业级：真实世界的编译器

| 系统 | 前端 | 中端/IR | 后端 | 说明 |
|---|---|---|---|---|
| GCC | 各语言前端 | GIMPLE | 各 CPU 后端 | 老牌巨兽 |
| LLVM/Clang | Clang(C/C++)/Rust/Swift… | LLVM IR (SSA) | 各 CPU | **现代基础设施**，做新语言都接它 |
| JVM | javac → 字节码 | 字节码 | JIT(C1/C2) | 运行时再编译热点代码 |
| CPython | 编译到字节码 | 字节码 | 解释器循环 | 为什么慢：没有 JIT（默认） |
| V8 | JS → 字节码 | 字节码 | TurboFan JIT | 兼顾启动和峰值 |

**几个让你"哇一下"的事实**：

1. **Babel/TypeScript 也是编译器**——"source-to-source 编译器"（转译器），前端再往前后挪一格。
2. **SQL 引擎是编译器**：SQL → 逻辑计划 → 物理计划 → 执行（查询优化器就是它的"优化阶段"）。
3. **正则引擎、JSON 解析器、Markdown 渲染器**都是词法/语法分析的近亲。
4. **LLVM** 让你写的 DSL 只需实现一个小前端接上 IR，就能获得世界级优化+全平台支持。

**课程考试**：
