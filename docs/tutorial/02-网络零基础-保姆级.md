# 第 2 章 · 网络零基础（保姆级）

> 本章目标：让你彻底理解"我的电脑是怎么和别人的电脑说话的"，并且亲手搭出一个**别的设备能访问**的网站。
> 学完标志：你能回答"为什么这个网站打不开"并自己排查出原因。
> 预计学习时间：2-3 周。

---

## 2.1 用"寄快递"理解一切网络

### 2.1.1 网络就是"电脑之间寄快递"
两台电脑要通信，和两个人互相寄快递一模一样：
| 快递世界 | 网络世界 | 名字 |
|----------|----------|------|
| 收件地址：上海市XX路1号 | 目标地址：`47.103.8.12` | **IP 地址** |
| 收件人具体门牌 | `:443`（后门数字） | **端口** |
| 寄快递要用货车、飞机 | 数据用"网线/光"传输 | **物理介质** |
| 快递单上写"易碎品、加急" | 数据包上的格式标记 | **协议** |
| 大件拆成多个箱子，编号运送 | 大文件拆成多个"包" | **数据包/分包** |
| 快递公司保证"送到" | 保证可靠传输的机制 | **TCP** |
| 平邮，不保证到不到但很快 | 不管到没到、只发 | **UDP** |

**把这张表读懂，你已经理解了网络的本质。** 剩下的全是细节。

### 2.1.2 两个基础概念
- **协议（Protocol）**：双方约定的"语言规则"。两个人通话要同一种语言，电脑通信也要同一套协议。最基础的协议族叫 **TCP/IP**。
- **分层**：网络被分成几层，每层只管自己的事（像快递系统分：装箱的、运输的、派送的）。工程师排错时，一层一层查——这个"分层排查法"你马上会学。

## 2.2 IP 地址：电脑的门牌号（**手把手教，包学包会**）

### 2.2.1 IP 地址长什么样
IP 地址是一个 32 位的数字，写成 4 段，比如：
```
192.168.1.10
```
每段取值 0-255（为什么是 255？因为每段是 8 个二进制位，2 的 8 次方减 1 = 255。不用懂二进制，先记住取值规则）。

> 更精确的说法：这叫 **IPv4 地址**。全世界 IPv4 地址已经发完了，所以有了新版本 **IPv6**（长这样：`2001:db8::1`，用冒号分隔 16 进制）。本章以 IPv4 为主，IPv6 概念相同，见过不慌即可。

### 2.2.2 两种 IP：私有的和公有的（**全网都在用，必懂**）
| 类型 | 例子 | 在哪用 | 比喻 |
|------|------|--------|------|
| **私有 IP**（内网） | `192.168.x.x`、`10.x.x.x`、`172.16.x.x~172.31.x.x` | 家里/公司的局域网内部 | 你家卧室的门牌，仅小区内有效 |
| **公网 IP** | 其他（如 `47.103.8.12`） | 互联网上唯一 | 小区的街道地址，全世界快递能寄到 |

**关键常识**：

- 你家路由器分给手机、电脑的都是**私有 IP**（192.168 开头）
- 你家的宽带有一个**公网 IP**（通常是运营商给的，还会变）
- 全世界的电脑**不能直接访问你的私有 IP**——这就是为什么家里电脑不能被外网直接访问，而云服务器（有公网 IP）可以。

### 2.2.3 两个特殊的地址（背下来）
- `127.0.0.1` = **本机**（俗称 localhost）。访问它 = 访问你自己这台电脑，永远不出家门。
- `0.0.0.0` = **"本机所有网卡"**。服务配置里写 `0.0.0.0:80` 意思是"从任何网卡来的访问我都接"。

### 2.2.4 怎么查自己的 IP（动手）
```bash
ip addr
```
输出里找 `inet` 开头的行：
```
inet 127.0.0.1/8 scope host lo                ← 本机地址
inet 192.168.1.10/24 brd 192.168.1.255 ...   ← 你的私有 IP（看你自己的数字）
```

- `192.168.1.10/24` 里的 `/24` 是"网段"标记（见下一节）

再试：
```bash
hostname -I      # 快速显示本机 IP（大写 i）
curl ifconfig.me # 显示你"出网"时的公网 IP——看看它是不是和上面不一样？（很可能不一样，因为你躲在路由器后面，这叫 NAT，2.3 节讲）
```

### 2.2.5 网段与子网掩码（**本章最烧脑的部分，跟我一步一步来**）

**先建直觉**：为什么要有"网段"？
> 小区概念。同一个小区（网段）的邻居，直接喊一声就能听见（直接通信）；外小区的人，要通过大门（网关）出去。
> 电脑判断"对方和我在不在同一个小区"，靠的就是 **IP + 子网掩码**。

**看一个例子**：

- 你的电脑：`192.168.1.10`，掩码 `255.255.255.0`（可写成 `/24`）
- 掩码的作用：**规定"IP 的前多少位是小区名，后多少位是门牌号"**
- `255.255.255.0` 的意思是：**前三段是小区，最后一段是门牌**
- 所以你家小区是 `192.168.1.x`，你有 3 个邻居设备（.1 路由器、.20 手机、.30 另一台电脑）都直接能通
- 你要访问 `192.168.2.10`（另一个小区）：**不在一个小区 → 必须通过网关（路由器）转发**

**/24 里的 24 是什么意思？** 掩码写成二进制有 24 个 1（255.255.255.0 = 24 个 1 + 8 个 0），简写成 `/24`。

**三种最常见的掩码（够用 90% 场景）**：

| 写法 | 掩码 | 小区容量（可用门牌数） | 例子 |
|------|---------|------------------------|------|
| `/24` | 255.255.255.0 | 254 个 | 家庭、小公司 |
| `/16` | 255.255.0.0 | 6 万多个 | 大公司、云平台 |
| `/8` | 255.0.0.0 | 1600 万个 | 超大网络 |

> 为什么 `/24` 是 254 个而不是 256 个？因为每段里**第一个地址是"小区名"（网络地址），最后一个是"广播地址"**，都不能分配给设备。256 - 2 = 254。
> 广播地址（.255）是干嘛的？"给全小区喊话"用的。

**【小练习】**（答案在下面）
1. `10.0.0.5/24` 这个地址，小区范围是什么？最多能放多少台设备？
2. `192.168.1.10` 和 `192.168.2.10`（都是 /24），它们直接通吗？
3. 那 `192.168.1.10` 和 `192.168.1.200` 呢？

<details>
<summary>答案</summary>
1. 小区是 10.0.0.x，容 254 台。2. 不通，不同小区，必须经过网关。3. 通，同一个小区，
具体通信细节叫"ARP 找邻居"（先不用学）。</details>

**关于"IP 加减法"和"二进制"**：看到这里你已经够用了。真正复杂的子网划分（比如 /26 能放几台）等你学到中级篇再练——届时候你已经有大量手感，一学就会。**现在别让"算不清 IP"拦住你前进。**

## 2.3 端口、NAT 与"网络是怎么连起来的"

### 2.3.1 端口：一台电脑上的"不同门"
一个 IP 是一栋楼，**端口就是一扇扇门**。同一台服务器既能提供网页（80/443 门），又能提供 SSH 远程（22 门）。

- 端口号范围：0-65535
- **必背"著名端口"**（就像记"110 是报警电话"）：

| 端口 | 服务 | 干什么的 |
|------|------|----------|
| 22 | SSH | 远程登录 |
| 80 | HTTP | 网页（明文） |
| 443 | HTTPS | 网页（加密） |
| 53 | DNS | 域名解析 |
| 25/465/587 | SMTP | 发邮件 |
| 143/993 | IMAP | 收邮件 |
| 3306 | MySQL | 数据库 |
| 6379 | Redis | 缓存 |
| 8080 | 备用 HTTP | 常见应用端口 |

**动手看本机哪些"门"开着：**
```bash
ss -tlnp
```
输出示例：
```
State   Local Address:Port   Process
LISTEN  0.0.0.0:22           sshd
LISTEN  0.0.0.0:80           nginx
```

- `LISTEN` = 这个服务在"守门"（等人连接）
- `0.0.0.0:22` = 任何网卡的 22 号门
- **这条命令是你以后判断"服务起没起"的第一利器**

### 2.3.2 NAT：为什么你家没公网 IP 也能上网
你家里的设备都是 192.168 私有地址，但这些地址在互联网上"不存在"。可你上网明明畅通无阻——**靠的是 NAT（网络地址转换）**。

> 人话版：全小区（你家）只申请了一个街道地址（宽带公网 IP）。所有包裹都由门口的门卫（路由器）统一代收代发：你寄快递时，写完家门牌（192.168.1.10）后，门卫会把它换成街道地址（公网 IP）再寄出去，并在小本本上记下"这是 3 号房寄的"；回信寄到街道地址，门卫查本本，把信交给 3 号房。
> **这就是为什么外网"不能直接找到你"，但你能访问外网。**

**引申常识**：所以家里要建网站给全世界看，要么有公网 IP + 端口映射（路由器上设置），要么用云服务器。**比赛学习中直接买云服务器最省事。**

### 2.3.3 路由器、网关、DNS 的分工（一句话版本）
- **网关**：你家小区的大门（通常是路由器 192.168.1.1）。去外网的流量都从这走。
- **路由器**：当网关的这台设备，管分发。
- **DNS**：互联网的"通讯录"。你说"百度"，它帮你查成 IP 地址。

```bash
ip route          # 看你的网关是谁
# 输出里 default via 192.168.1.1 —— 192.168.1.1 就是你家大门
```

## 2.4 DNS：互联网的通讯录（动手玩明白）

### 2.4.1 为什么需要 DNS？
人能记"百度的网址是 baidu.com"，记不住"180.101.50.242"。DNS（Domain Name System，域名系统）就干一件事：**把域名翻译成 IP**。

### 2.4.2 自己动手查询（这节全是实验）
```bash
# 安装查询工具（bind9 套件里的 dig）
sudo apt install -y dnsutils

# 查询 baidu.com 的 IP
dig baidu.com
```
输出里看 **ANSWER SECTION**：
```
baidu.com.      123  IN  A  110.242.68.66
```
表示 baidu.com → 110.242.68.66。（每次查到的可能不一样，大公司有很多服务器，正常。）

```bash
nslookup baidu.com      # 更简单的查询工具
nslookup baidu.com 8.8.8.8   # 指定用谷歌的 DNS 服务器来查
```

### 2.4.3 域名是怎么被"翻译"的（讲清楚这一层，你就超过大多数新手了）
当你访问 `www.baidu.com`，背后发生：
1. 电脑先问自己："我有没有缓存过？" 有 → 直接用。
2. 没有 → 问**本地配置的 DNS 服务器**（通常是你家路由器，或运营商/公共 DNS）
3. 这个 DNS 服务器如果也不知道，就帮忙四处打听（问根服务器 → 问 .com 服务器 → 问 baidu.com 的服务器），查到后告诉你，并自己缓存一份。
4. 你拿到 IP，开始连接。

```bash
cat /etc/resolv.conf     # 看你的电脑用的是哪个"通讯录"（DNS 服务器）
```
输出类似：
```
nameserver 127.0.0.53      # Ubuntu 上的本地缓存 DNS
```

### 2.4.4 域名里的层级（看懂网址结构）
```
www  .  baidu  .  com
 |        |       |
子域名    主名    顶级域（TLD）
```

- `com` 商业、`org` 组织、`cn` 中国、`edu` 教育……
- `www` 是子域名（很多网站现在省略 www 也能访问）
- **世界赛考点提醒**：比赛里要你会搭 DNS 服务器、配置 A 记录/CNAME 记录/反向解析——这些是中级篇的内容，现在先理解概念。

## 2.5 网络排查五大命令（**排障武功，招招必学**）

**排错思路（四层排查法）**：
```
① 物理/网卡 → ② IP/网关 → ③ DNS → ④ 目标服务/防火墙
每一层都有对应的命令去"验尸"。
```

### ① `ping` — 通不通？
```bash
ping baidu.com
```

- 输出 `64 bytes from ... time=32 ms` = 通了（time 是往返耗时）
- 输出 `unknown host` = **DNS 问题**（名字都没翻译出来）
- 输出 `Destination Host Unreachable` / 一直不动 = **网络不通**（IP 层问题）
- 按 `Ctrl + C` 停止

```bash
ping -c 4 192.168.1.1    # 只发 4 个包，然后自动停
```
**排错口诀：先 ping 网关（192.168.1.1），再 ping 8.8.8.8，再 ping 域名。**

- 网关都不通 → 你到自己家的路都断了（网线/网卡/内网问题）
- 网关通、8.8.8.8 不通 → 你家到外面的路断了（路由器/运营商问题）
- 8.8.8.8 通、域名不通 → **百分百 DNS 问题**

### ② `curl` — 网页拿得到吗？（**排障之王**）
```bash
curl http://baidu.com
```
→ 直接把网页源码吐在屏幕上。

```bash
curl -I http://baidu.com     # 只看"名片"（响应头）
```
输出：
```
HTTP/1.1 200 OK        ← 200 = 一切正常（状态码见下表）
Server: nginx          ← 对方用什么软件
```
**常见 HTTP 状态码（背）**：
| 码 | 含义 | 人话 |
|----|------|------|
| 200 | OK | 成功 |
| 301/302 | 重定向 | "你要的东西搬家了，去新地址" |
| 403 | Forbidden | "我知道你要啥，就不给你"（权限） |
| 404 | Not Found | "没这个东西"（路径写错） |
| 500 | Server Error | "服务器自己出错了"（看服务器日志） |
| 502 | Bad Gateway | "后面的程序挂了"（反向代理找不到后端） |
| 503 | Service Unavailable | "服务忙/在维护" |

```bash
curl -v http://localhost     # -v 详细模式：显示连接全过程（连IP、发请求、收响应）
```
**这个 -v 输出是排障圣经**。以后网站访问不了，先 `curl -v` 看卡在哪一步。

### ③ `ss -tlnp` — 我本机开了哪些门？（前面学过，复习）
服务起没起、监听哪个端口，全看它。

### ④ `traceroute` — 数据走过了哪些"驿站"？
```bash
sudo apt install -y traceroute
traceroute baidu.com
```
→ 显示数据包路过的每一个路由器（每一跳）。哪里开始不通，问题就在那里之后。

### ⑤ `tcpdump` — 抓包（进阶，先看个例子）
```bash
sudo tcpdump -i any port 80 -c 5
```
→ 抓 5 个 80 端口的包就停。另开一个窗口 `curl http://baidu.com`，你能看到"网络侦探视角"的数据流动。
（看懂看不懂没关系，先知道有这么个终极武器。中级篇会用。）

### 【实战排错演练】
故意制造一个故障再修好它（**请一定要做，这是本章精华**）：
```bash
sudo systemctl stop nginx           # 制造故障：把网站关了
curl -v http://localhost            # 观察报错：Connection refused
```
**思考**：报错是"连接被拒绝"——说明什么？说明"门"没开（服务没监听）。那么：
```bash
sudo systemctl status nginx         # 查服务状态 → inactive (dead)
sudo systemctl start nginx          # 修复
curl http://localhost               # 验证恢复
```
**恭喜，你完成了人生第一次正规的"故障排查闭环"：发现→观察→定位→修复→验证。** 这就是运维工程师工资的由来。

## 2.6 防火墙：小区的门禁（概念 + ufw 上手）

防火墙决定"哪些门允许谁进出"。Ubuntu 上简单好用的是 **ufw**（Uncomplicated Firewall，"不复杂防火墙"）。

```bash
sudo apt install -y ufw
sudo ufw status               # 看状态（默认 inactive 未启用）
sudo ufw allow 22             # 放行 22 端口（SSH）★ 先放行它，否则你会把自己锁在门外！
sudo ufw allow 80             # 放行 80（网页）
sudo ufw allow 443            # 放行 443（HTTPS）
sudo ufw enable               # 启用（会问 y/n）
sudo ufw status               # 现在能看到放行的规则
```

**血的教训（必须记住）**：
> 在**云服务器**上开防火墙前，**先确认 22 端口是放行的**，否则你 SSH 一断，就永远进不去了（云控制台有"救援模式"可以救，但很折腾）。

**删除规则：**
```bash
sudo ufw status numbered      # 看带编号的规则
sudo ufw delete 3             # 删第 3 条
```

**和云平台"安全组"的关系**：云服务器有**两道门**：
1. 云平台侧的**安全组**（在网页控制台里设置，"云的大门"）
2. 服务器内部的**防火墙**（ufw，"家里小门"）
**两道门都要放行，服务才能从外面访问到！** 新手 90% 的"部署了但访问不了"，都是忘了其中一道。

## 2.7 综合实战 A：搭一个网站，让别的设备访问它

**目标**：你亲手部署的网站在**另一台设备**（比如你手机/另一台电脑）上打开。

### 2.7.1 如果你用的是【云服务器】方案
1. 确认 nginx 跑着：`sudo systemctl status nginx`（没装就 `sudo apt install -y nginx`）
2. 云控制台 → 安全组 → 放行 80 端口（教程里叫"添加入方向规则：TCP 80，来源 0.0.0.0/0"）
3. 服务器上放行：`sudo ufw allow 80`（如果 ufw 开着）
4. 在**手机浏览器**输入 `http://你的公网IP` →
   看到 **"Welcome to nginx!"** → 🎉 **你成功了！！**

**如果打不开**，按这个顺序排查：
1. 服务器本机 `curl http://localhost` → 通吗？（不通 → nginx 问题）
2. `sudo ss -tlnp | grep 80` → nginx 在 80 端口听着吗？
3. 云安全组放行了吗？（最常见坑）
4. 服务器防火墙放行了吗？
5. 还不行 → 从手机 `ping 你的公网IP` 通吗？

### 2.7.2 如果你用的是【虚拟机】方案
1. 先查虚拟机 IP：`hostname -I`（比如 192.168.100.130）
2. 在你的宿主机（Windows）浏览器访问 `http://192.168.100.130`
3. 打不开的话，检查虚拟机网络模式：VMware 用 **NAT** 模式时宿主机访问不了虚拟机，把虚拟机网络改成 **桥接（Bridged）** 模式即可（虚拟机设置 → 网络适配器 → 桥接）

### 2.7.3 让网站显示你自己的内容（成就感拉满）
```bash
# 修改 nginx 的默认网页
sudo nano /var/www/html/index.html
```
把内容改成：
```html
<!DOCTYPE html>
<html>
<head><meta charset="utf-8"><title>我的第一个网站</title></head>
<body>
  <h1>你好，世界！</h1>
```

## 2.8 综合实战 B：理解"域名 → 自己的网站"全流程（进阶选做）

**目标**：给网站配一个"名字"，理解 DNS 的实战价值。
1. 买一个便宜域名（几块钱/年，腾讯云/阿里云搜"域名注册"，选 `.top` `.xyz` 最便宜的）
2. 域名控制台 → 解析设置 → **添加记录**：
   - 记录类型：`A`
   - 主机记录：`@`（代表域名本身）或 `www`
   - 记录值：`你的服务器公网 IP`
3. 等待几分钟，本地测试：
   ```bash
   dig 你的域名.com          # 应该返回你的 IP
   curl http://你的域名.com   # 应该返回 Welcome to nginx
   ```
4. 手机浏览器访问 `你的域名.com` → 成功！

**你现在能让全世界的人通过"名字"访问你的网页了。** 你现在做的事，和真正互联网网站的运转方式已经一模一样。
