## 16.1 比赛体系全貌（先知道自己要打什么）

### 三级火箭
```
① 校级/市级选拔  →  ② 省赛     →  ③ 全国选拔赛 → 国家集训队 → 世界赛
   （入门）          （省前几名）     （全国前几名）    （多轮淘汰）   （单挑全世界）
```

### 世界赛云计算到底怎么比
- **4 个模块**（以 2024 里昂为例，见本资料包 `test-projects/LYON2024-评分点全录.md`）：
  - **Module A - Linux**：LDAP / CA / Samba / DNS / WireGuard / HAProxy / 防火墙…（52 个评分点）
  - **Module B - Windows**：AD 域 / GPO / DFS / IIS / CA / RRAS…（8 台主机）
  - **Module C - 云架构**：AWS 综合架构设计（VPC/计算/存储/数据库/高可用/安全）
  - **Module D - 排障**：预埋故障的系统 + 工单，限时修复（第 7 章的场景考试版）
- **评分方式**：专家用**评分脚本逐项实测**（不是看你配了没有，是测"能工作吗"）
- **时长**：每个模块 3~7 小时，连续多天

### 各国风格差异（决定训练侧重）
| 比赛 | 风格 | 侧重 |
|------|------|------|
| 世界赛 | 传统基础设施 + 排障 + 云 | Linux/Windows 服务硬功夫 |
| 韩国赛 | AWS 全家桶 + Terraform + 性能/成本 | 自动化 + SRE 化 |
| 中国国赛 | OpenStack + 容器云 + 公有云 | 平台广度 |
| 葡萄牙/加拿大 | 混合型 | AWS + 传统服务 |

## 16.2 用真题训练的标准流程（黄金四步）

**这一步比"再做一套题"重要十倍。** 任何一道真题（本资料包里有 300+ 道）都按这个流程练：

### 第 1 步：裸做（赛前状态）
- 只拿**题面**（不看答案！）
- 按比赛时长限时（韩国题 4 小时就是 4 小时）
- 允许查官方文档（比赛也允许），但**不许看题解**
- 一开始肯定做不完——**正常。目的是暴露弱点。**

### 第 2 步：对照评分（残酷自检)
做完后，对照**评分标准**逐条打分：
- 本资料包 → `test-projects/korea-历年真题文本/*_grad.txt`（韩国评分标准）
- `test-projects/LYON2024-评分点全录.md`（世界赛评分点）
- 打分要诚实！"大概能过"= 不得分（评分脚本是机器测，不是人情测）

### 第 3 步：差距分析（写下来）
做一个"失分表"：

| 失分点 | 原因 | 属于哪章知识 | 补课动作 |
|--------|------|-------------|----------|
| ECR 镜像扫描没过 | 基础镜像的 CVE 太多 | 10 章（Docker） | 学换基础镜像+更新依赖 |
| 告警规则没配 | 忘了 PrometheusRule | 14 章（监控） | 重做 14.2.4 |
| 成本超了 | 节点没缩容 | 12 章（AWS）+ 14 章 | 学 Karpenter/Cluster Autoscaler |

### 第 4 步：重做（把弱项打到肌肉记忆）
只重做**失分的那 20%**，直到满分。然后进入下一道题。
> **学习的秘密：不是你做了多少题，而是你把多少错题变成了肌肉。**

## 16.3 带练演示：解剖一道韩国真题（教学样例）

让我们拿**韩国 2026 全锦赛第 1 任务**（本包里有完整题面和题解）演示全过程。

### 第 1 步：读题（5 分钟提炼要求）
题面核心（简化版）：
- 把 Web 应用部署到 AWS：EKS 集群 + ECR 镜像 + CloudFront + Lambda + DynamoDB
- 监控栈：Prometheus + Grafana + Fluent Bit
- 安全：KMS 加密、WAF 保护、镜像无高危漏洞
- 用 `STUDENT_ID` 变量区分每位选手

**读题动作**：把所有"动词"圈出来——创建、部署、配置、限制、保护。**每个动词都是评分点。**

### 第 2 步：列资源清单 + 变量表
```
资源清单：
- VPC（子网/路由/网关）
- EKS 集群 + 节点组
- ECR 仓库（存应用镜像）
- CloudFront（CDN + Function 路径改写）
- Lambda + DynamoDB（预约查询功能）
- KMS（每服务一把钥匙 ×5）
- WAF（挂 CloudFront/ALB）
- Grafana（监控面板）

变量表：
STUDENT_ID=<比赛发的编号>  ← 所有资源名都要带它（防选手间冲突）
区域：ap-northeast-2（题面规定）
Grafana 账号：skills-<ID>-admin
```

### 第 3 步：对照评分标准逆推"检查清单"
评分标准里的每一句都是一条"验收命令"，把它变成自己的 checklist：
```
□ CloudFront 状态是 Deployed
□ ECR 扫描无 Critical/High
□ Grafana 能登录（skills-<ID>-admin），有 5 个面板
□ 应用能通过 CloudFront 访问（200）
□ WAF 拦住了无 UA 请求（403）
□ KMS 里有 5 把钥匙
...
```
**每次做完一个单元，就用对应的"验收命令"自测一次。** 这是职业选手和业余选手的最大区别。

### 第 4 步：实施顺序（把 4 小时花在刀刃上）
```
0:00-0:15  通读题面 + 列清单 + 定义 STUDENT_ID
0:15-0:45  Terraform 写基础网络 + EKS（最长步骤放前面，等集群时干别的）
0:45-1:30  应用镜像构建 + 推 ECR + 部署到 EKS（同时配监控）
1:30-2:30  CloudFront + Lambda + DynamoDB 功能链
2:30-3:15  安全项收尾（KMS/WAF/扫描修复）
3:15-3:45  全量自测（照着 checklist 跑一遍）
3:45-4:00  修复自测发现的问题 + 留痕
```

### 第 5 步：对比选手题解
打开 `github-repos/2026-natl-cc-task1-main/`，对照：
- 他的 `Makefile`（`make up` 一键）比你的手动操作快多少？
- 他的模块划分、变量管理有什么值得抄？
- 他写的 checklist 文件（你有吗？）
**把差距写成下次的改进项。**

## 16.6 比赛现场十条军规

1. **前 15 分钟只读题**，列清单、排优先级（"必拿/可争/放弃"三档）
2. **先定义变量**（STUDENT_ID 之类），全局引用
3. **边做边自测**：每完成一单元，立即用评分标准对应的命令验证
4. **卡住超 10 分钟就跳过**——先捡分，回头再来
5. **改配置前先备份**，改完先 `-t`/`plan` 再 reload/apply
6. **题目和评分标准冲突时，以评分标准为准**（韩国题面明文规定）
7. **定时保存/提交**（云上操作无法撤销，大改动前先确认现状）
8. **留 15% 时间做终检**：对照 checklist 全量跑一遍
9. **时间到就停手**，别再改（改崩了连已拿的分都没了）
10. **每天比赛结束写复盘**（失分表），第二天早上先看它
