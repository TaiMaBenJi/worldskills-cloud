# ⚡ 72 小时冲刺作战手册（比赛应急版）

> 适用：3 天后就要上考场（云计算类比赛）。
> 战略：**放弃"全面精通"，主攻"高频题型 + 操作模板 + 应急预案"。**
> 目标：会做的题全拿分，没见过的题能动手、能得部分分。

---

## 0. 战前认知（先读，30 分钟，改变你的三天）

### 0.1 现实检验（不许自欺）
- 三天 ≠ 精通云计算。任何人都做不到，爱因斯坦来了也不行。
- 但三天 = **进入"能打仗"状态**：考试考的从来不是"你懂多少"，而是"**在规定时间内，你把多少道题的操作做出来了**"。
- 拿奖的人不一定懂最多——**他们只是把常考题型练成套路 + 在考场上把能拿的分全拿了**。

### 0.2 三天后的你（合理目标）
- 常见题型的操作正确率：80%+
- 见过的操作：30 秒内动手；没见过的：能摸索着做出来
- 考场不慌、有检查清单、有应急预案
- **这就足够和大多数对手拉开差距了。**

### 0.3 三天总方针
```
Day 1：Linux + 网站部署一条龙（一切题型的地基，最高频送分题）
Day 2：容器(Docker/K8s) + 云平台操作（比赛重头戏）
Day 3：真题限时模拟 + 查漏 + 背速查卡（进入实战状态）
```

### 0.4 三条铁律
1. **所有操作必须亲手敲一遍**——看会 ≠ 会。三天里"看过"的部分考场上全忘，只有"敲过"的能留下。
2. **死磕不超过 10 分钟**：任何操作卡住，立刻切到"速查卡找命令"或跳过，练完回头再看。
3. **每天结束前，把当天所有操作"闭卷重做一遍"**（这是把"会"变成"稳"的唯一方法）。

## Day 1 · Linux + 网站部署一条龙（10-12 小时）

> 为什么先学这个：**几乎所有云计算比赛的每道题都从"登录 Linux 敲命令"开始。** 这是送分题的根。

### 上午（3.5h）：Linux 必会 40 命令（按场景记，不按字母表背）

**准备环境**：本地虚拟机跑一台 Ubuntu（教程第 1 章方案 A），或直接用你的云服务器。

**【场景1：找路与看东西】**（30 分钟练熟）
```bash
pwd                    # 我在哪
ls -lh                 # 看有什么（带大小）
cd /etc                # 去哪
cat 文件               # 看内容
head -20 文件          # 看前20行
tail -50 文件          # 看后50行（考试看日志用这个）
grep "关键词" 文件      # 找关键词（考试超高频）
```

**【场景2：搞文件】**（30 分钟）
```bash
mkdir -p /opt/mytest         # 建目录
cp a.txt b.txt               # 复制
cp -r 目录1 目录2             # 复制目录
mv a.txt /tmp/               # 移动/改名
rm -f a.txt                  # 删文件（-r 删目录）
touch new.txt                # 建空文件
vim 文件                     # 编辑（i 进入, Esc 退出, :wq 保存, :q! 不保存退出）
tar -czvf pack.tar.gz 目录    # 打包
tar -xzvf pack.tar.gz        # 解包
```

**【场景3：权限与用户】**（40 分钟）
```bash
chmod 755 脚本.sh            # 加权限（755=人人可读可执行）
chmod +x 脚本.sh             # 加执行权限
chown user:user 文件         # 改属主
sudo 命令                    # 用管理员身份
useradd -m zhangsan          # 建用户
passwd zhangsan              # 改密码
id zhangsan                  # 查用户
```

**【场景4：装软件与服务】**（40 分钟）——**考试必考**
```bash
apt update && apt install -y nginx      # 装软件（Ubuntu）
systemctl start nginx                   # 启动
systemctl enable nginx                  # 开机自启（考试常要求！）
systemctl status nginx                  # 看状态（出问题第一步）
systemctl restart nginx                 # 重启（改配置后必做）
```
**服务管理的万能排查链**（背下来）：
```
不会用 → systemctl status 看状态 → journalctl -u 服务名 -n 50 看日志
```

**【场景5：网络与防火墙】**（40 分钟）——**考试必考**
```bash
ip addr                    # 看IP
ss -tlnp                   # 看哪些端口在听（验证服务起没起）
curl http://localhost      # 测试访问
ping -c 3 8.8.8.8          # 测网络
ufw allow 80               # 防火墙放行（Ubuntu）
ufw allow 22 && ufw enable # 先放22再开防火墙（否则锁死自己）
firewall-cmd --add-port=80/tcp --permanent && firewall-cmd --reload   # CentOS系
```

**【场景6：进程与排障】**（30 分钟）
```bash
ps aux | grep nginx        # 找进程
kill -9 PID                # 杀进程
df -h                      # 看磁盘（满了会出各种怪问题）
free -h                    # 看内存
top                        # 实时看资源
```

### 下午（3.5h）：网站部署"一条龙"（**全场最高频的大题模板**）

**目标**：从裸机到"浏览器能访问的动态网站"，全程亲手做 2 遍。

**① 静态网站（30 分钟）**
```bash
apt install -y nginx
echo "<h1>Hello 比赛</h1>" > /var/www/html/index.html
systemctl restart nginx
curl http://localhost     # 验证
```

**② 配置"虚拟主机"（40 分钟）**——考试常考"用域名 XX 访问"
```bash
# 建站点目录和页面
mkdir -p /var/www/site1
echo "<h1>Site1 OK</h1>" > /var/www/site1/index.html

# 写配置
cat > /etc/nginx/sites-available/site1.conf <<'EOF'
server {
    listen 80;
    server_name site1.test;
    root /var/www/site1;
    index index.html;
}
EOF

# 启用 + 测试 + 重启（三步固定流程！）
ln -s /etc/nginx/sites-available/site1.conf /etc/nginx/sites-enabled/
nginx -t && systemctl restart nginx

# 本地验证（考试没域名就用 hosts 或 Host 头）
curl -H "Host: site1.test" http://localhost
```

**③ 装数据库（40 分钟）**——考试必考"建库建用户"
```bash
apt install -y mysql-server
mysql     # 进入数据库（root 直接进）
```
```sql
CREATE DATABASE appdb CHARACTER SET utf8mb4;
CREATE USER 'appuser'@'localhost' IDENTIFIED BY 'App123!';
GRANT ALL ON appdb.* TO 'appuser'@'localhost';
FLUSH PRIVILEGES;
USE appdb;
CREATE TABLE users (id INT PRIMARY KEY AUTO_INCREMENT, name VARCHAR(50));
INSERT INTO users (name) VALUES ('test1'),('test2');
SELECT * FROM users;
```
**备份/恢复（高频考点）**：
```bash
mysqldump -u root appdb > /root/appdb.sql          # 备份
mysql -u root appdb < /root/appdb.sql              # 恢复
```

**④ 动态网站（PHP 为例，40 分钟）**
```bash
apt install -y php-fpm php-mysql
# nginx 配置加 PHP 处理块：
#     location ~ \.php$ {
#         include snippets/fastcgi-php.conf;
#         fastcgi_pass unix:/run/php/php8.1-fpm.sock;
#     }
# 测试页面：
echo "<?php echo 'PHP OK'; phpinfo(); ?>" > /var/www/site1/info.php
# 重启并验证
```

**⑤ HTTPS（30 分钟，能加分）**
```bash
mkdir -p /etc/nginx/ssl && cd /etc/nginx/ssl
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout site.key -out site.crt -subj "/CN=site1.test"
# nginx 加 443 ssl 配置段 → nginx -t → 重启
```

**⑥ 全流程闭卷重做（30 分钟）**：合上所有资料，从空环境重新部署一遍"静态站+数据库"。

### 晚上（3h）：官网文档 + 真题摸底
1. **1h**：本资料库《保姆级教程》第 1-3 章快速过一遍（你已练过的部分，只看"出错了怎么办"小节）
2. **1.5h**：找 1 套本资料库里的真题（`test-projects/cn-domestic/` 里挑个短的）限时做——**不为做对，为暴露弱点**
3. **0.5h**：把今天所有卡过的点，写进"个人坑清单"（考前一天重点复看）

## Day 2 · 容器 + 云平台（10-12 小时）

### 上午（3.5h）：Docker 全流程（**国赛容器云必考**）
```bash
# 安装
apt install -y docker.io && systemctl enable --now docker

# 核心 12 命令（练到闭眼能敲）
docker pull nginx:latest          # 拉镜像
docker images                     # 看镜像
docker run -d -p 8080:80 --name web1 nginx    # 跑容器（-d后台 -p端口映射 --name命名）
docker ps                         # 看运行中的
docker ps -a                      # 看全部
docker logs web1                  # 看日志
docker exec -it web1 bash         # 进容器
docker stop web1 / docker start web1 / docker rm web1   # 停/启/删
docker rm -f web1                 # 强删
```
**Dockerfile 写镜像（高频）**：
```dockerfile
FROM nginx:latest
COPY index.html /usr/share/nginx/html/
EXPOSE 80
```
```bash
docker build -t mysite:v1 .       # 构建
docker run -d -p 8081:80 mysite:v1
```
**Compose（大分题）**：
```bash
apt install -y docker-compose-v2
# docker-compose.yml（写好两服务：web+db）
docker compose up -d
```

### 下午（3.5h）：K8s 常用命令（**容器云得分主力**）
> 用 minikube 或考场给定集群。记住：**K8s 考的大多是"命令 + YAML 模板"，不是原理。**

**15 个必会命令**：
```bash
kubectl get nodes / pods / svc / deploy -A     # 看东西（最常用）
kubectl create deployment web --image=nginx --replicas=2   # 建
kubectl expose deployment web --port=80 --type=NodePort    # 暴露服务
kubectl scale deployment web --replicas=4      # 扩缩容
kubectl get pods -o wide                       # 看详情
kubectl describe pod <名>                      # 排障第一命令
kubectl logs <名>                              # 看日志
kubectl exec -it <名> -- sh                    # 进容器
kubectl apply -f xxx.yaml                      # 应用文件
kubectl delete -f xxx.yaml                     # 删除
kubectl get pods -w                            # 实时观察
```

**YAML 模板背 2 个就够用**（Deployment + Service），考试直接改名字用：
```yaml
# deploy.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels: {app: web}
  template:
    metadata:
      labels: {app: web}
    spec:
      containers:
      - name: web
        image: nginx
        ports: [{containerPort: 80}]
---
apiVersion: v1
kind: Service
metadata:
  name: web-svc
spec:
  selector: {app: web}
  ports: [{port: 80, targetPort: 80}]
  type: NodePort
```
```bash
kubectl apply -f deploy.yaml
kubectl get pods,svc
minikube service web-svc     # 打开访问
```

### 晚上（3h）：云平台操作路径（公有云题模板）

```
3. 上传/选择镜像 → 创建实例规格
4. 创建实例（绑安全组、密钥对）
5. 绑定浮动 IP → SSH 登录
6. 部署应用 + 验证
```

## 考场生存手册（考试当天核心 8 条）

1. **开考前 10 分钟：通读全部题目**，标出"必做/能做/放弃"三档（先拿稳拿的分）
2. **时间三三制**：前 1/3 时间做完所有你会做的 → 中 1/3 攻中等难度 → 后 1/3 补漏检查
3. **每道题做完立即验证**（curl/浏览器/命令查），别攒着
4. **卡 10 分钟就跳过**——回头再来，往往一眼看出问题（大脑后台在干活）
5. **改配置先备份**：`cp 配置 配置.bak`——改坏了能回滚
6. **改完必重启**：`nginx -t && systemctl restart nginx`——考试丢分重灾区
7. **每完成一题，在草稿纸打勾**——防止漏题，稳定心态
8. **交卷前 15 分钟**：检查清单过一遍：服务是否 enable（开机自启）、防火墙、密码是否按要求改了

## 心态急救（考前/考场焦虑处理）

- **手抖 = 正常生理反应**，所有人都有。做 3 次深呼吸（吸4秒→憋4秒→呼6秒）。
- 遇到完全不会的题：**写已知的**（比如"这台机器 IP 是 X，服务已启动"）——很多题有过程分。
- 记住：**你不是去拿满分的，你是去比"谁丢分少"的**。把会做的全做对，你就赢了大多数对手。
- 考完不对答案、不回头，下一场是全新的。
