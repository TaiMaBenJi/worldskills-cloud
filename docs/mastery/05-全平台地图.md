# 精通之路 05 · 全平台地图：从"只会一朵云"到"云的通用语者"

> 只会 AWS 的人不是云计算母语者，是"AWS 方言者"。真正的母语者可以站在任何一朵云的控制台前，10 分钟内找到他要的一切。
> 本篇：各平台定位 + 核心服务超级对照表 + "两周学会一朵新云"的方法论。

---

## 0.1 先破除一个心理障碍

**"学第二个云要重头再来？"**——不需要。
你学 AWS 时花的 80% 时间学的是**概念**：什么是 VPC、为什么要有负载均衡、对象存储和块存储的区别。这些概念在任何平台都一样。
剩下 20% 才是"方言"：这个平台的按钮在哪、服务叫什么名字、CLI 语法。

**所以：第二朵云的学习成本 ≈ 第一朵的 20%。** 而且每多学一朵，边际成本继续降低。

## 0.4 "两周学会一朵新云"方法论（可复制流程）

以"从 AWS 转 Azure"为例：

### 第 1-2 天：建立概念映射
- 把上表 Azure 列读三遍，写出"哪些概念完全对应 / 哪些有细微差异 / 哪些是 Azure 独有"
- Azure 独有重点：**Entra ID 的地位**（不只是 IAM，是整个微软生态的身份中枢）、**Resource Group**（资源组——AWS 没有的"资源打包"概念）

### 第 3-5 天：跑通五个核心实验
在目标云上做同样五件事（每件都在 AWS 做过）：
1. 建 VPC + 子网 + 虚机 + SSH 登录
2. 建对象存储 + 上传文件 + 设置公开访问
3. 建托管数据库 + 连接
4. 建负载均衡 + 两台机器
5. 建监控告警

### 第 6-8 天：读官方"well-architected"文档
每个云都有架构最佳实践白皮书（Azure 叫 Well-Architected Framework）。读它 = 了解这个平台的"三观"和陷阱。

### 第 9-12 天：做一个完整项目
把你在 AWS 做过的某项目在目标云原样重建（如"带监控的博客系统"）。**从零到上线的完整闭环，是"会用"到"会"的分界。**

### 第 13-14 天：考个入门认证（可选但推荐）
Azure AZ-900 / 阿里云 ACP 入门级——以考促学，还能给简历加一行。

## 0.5 各平台精通路线图

### AWS（母语平台）——建议投入总学习时间的 50%
```
入门：Cloud Practitioner（可选，1 周）
核心：Solutions Architect Associate（2-3 个月，含大量动手）
进阶：Developer / SysOps 任一（1-2 个月）
深度：Solutions Architect Professional（3-6 个月）
专项：Security / Networking / Database / ML 各 1-2 个月
```
配套习惯：每月读一次 AWS What's New（知道世界在变）。

### Azure——建议 15%
```
AZ-900 → AZ-104（管理员，最实用）→ AZ-305（架构师）
重点攻克：Entra ID（比 IAM 复杂）、混合云（Arc）、企业采购模式（EA）
```

### GCP——建议 10%
```
Cloud Digital Leader → Associate Cloud Engineer → Professional Architect
重点体会：BigQuery（数据神器）、GKE（最优雅的 K8s）、Google 的"开发者友好"哲学
```

### 中国云（至少一朵精通，考虑就业）——建议 20%
```
阿里云：ACP（云计算）→ ACE（架构师）；重点是生态产品线（电商/大数据全家桶）
华为云：HCIA → HCIP → HCIE；重点是政企场景与信创生态
腾讯云：TCP 认证；重点是音视频/游戏解决方案
```
> 国内就业的现实建议：**AWS + 一朵国内云** 是"外企/出海 + 国内岗位"通吃的组合。

### 私有云 & 边缘——建议 5%
```
OpenStack：理解架构 + 部署一个最小环境（国赛/政务项目用）
VMware：VCP 或至少理解 vSphere 全家
边缘：Cloudflare Workers / Lambda@Edge 玩一个边缘应用
```

## 0.6 多云的"三层同构"心法（把知识挂到正确的高度）

学任何云服务时，强迫自己回答三层：
1. **概念层**（不变）：这是"消息队列"——异步解耦用
2. **接口层**（半变）：AWS 叫 SQS，Azure 叫 Storage Queue，但都有标准协议（AMQP 等）可对接
3. **实现层**（全变）：按钮位置、配额限制、计费方式——查文档解决

**把知识尽可能挂到"概念层"**，你的知识就会像水一样，倒进任何容器都能成形。

> 检查标准：当你看到一篇"Azure 消息服务新功能"的文章，能自动翻译成"哦，相当于 AWS 的 XX 加了个 YY"，你就已经跨过平台壁垒了。

## 0.7 云平台的"方言特色"鉴赏（进阶趣味）

每个平台都带着自己的"出身性格"，理解它们能让你预判服务的风格：
- **AWS**：超市型——200 多个服务，很多是"先做了再说"，命名混乱但全。哲学："给你原语，自己组装"
- **Azure**：企业型——一切围绕"企业 IT 治理"设计，命名工整，和微软全家桶深度耦合。哲学："和你现有的 IT 世界无缝"
- **GCP**：极客型——少而精，数据/AI/K8s 三条线做到极致，产品体验最好。哲学："用最优雅的方式解决"
- **阿里云**：电商实战型——"双十一"锤炼出来的产品，扛峰值能力全球第一梯队。哲学："场景驱动"
- **华为云**：政企型——合规、安全、驻场服务。哲学："自主可控，深度服务"

**这些性格不是八卦——它决定了"什么需求去哪朵云"的直觉。**
（例：要在欧洲做 AI 训练→GCP；要接企业 AD 生态→Azure；要出海电商大促→AWS/阿里；要做政务合规→华为云。）
