# 精通之路 02 · 精通阶梯：五级自测与升级任务

> 不知道自己水平的人，既容易妄自菲薄，也容易盲目自满。
> 本篇给你一套**可自测的五级体系**：每级有明确的"通过标准"和"升级任务"。诚实打分，看清自己，然后往上爬。

---

## 使用说明

- 每一级的"自测题"**必须不看资料、独立完成**才算通过
- 通过标准：该级所有必测题 ≥80% 完成度
- 找到你的级别后，只练"升级任务"，不要重复练已会的（**舒适区没有成长**）

---

## L1 · 使用者（"会跟着做"）

### 典型特征
- 能照着图文教程完成部署，但教程没有的地方就卡住
- 知道一些名词（"服务器""数据库"），但说不清本质
- 遇到报错第一反应是"搜一下这段错误信息"

### 自测题（请动手，不许查教程）
1. 在任意 Linux 机器上装好 Nginx 并让浏览器访问到它
2. 解释你刚才做的事里，ip、端口、DNS 各自起了什么作用
3. 把一个文件从本机传到服务器（用 scp 或面板都算）
4. 说出"HTTP 404"和"502"的差别
5. 服务挂了，找到日志并说出它为什么挂

### 升级任务（L1 → L2）
- [ ] 完成本资料库《保姆级教程》第 1-3 章，并做完每章的自检清单
- [ ] 把"跟着教程做"改成"看着需求做"：给自己 3 个新需求（如"部署一个静态博客"），只允许查官方文档完成
- [ ] 学会一个命令行工具链：ssh / scp / 系统服务管理
- [ ] **戒掉"复制粘贴不理解"**：每敲一个命令，写下它每个参数的含义

> 预计时间：1-2 个月（每天 2 小时）

---

## L2 · 操作者（"不依赖教程"）

### 典型特征
- 给你需求，你能独立部署，但**离开文档就心虚**
- 会用 3-5 个核心服务（如 EC2/S3/RDS）
- 但换个云平台、或需求复杂一点，就回到"搜教程"状态

### 自测题
1. 给你一个空 AWS 账号和一句需求"搭一个能抗 1000 人同时在线的投票网站"，独立完成（可用官方文档）
2. 给你一台有故障的服务器（服务不通），30 分钟内定位并修复（不查教程）
3. 写出你用的平台里"所有网络类服务"的清单，并说出各自的定位
4. 用命令行（不是控制台）完成：创建存储桶、上传文件、设置权限
5. 解释你的架构里每个组件的"如果坏了会怎样"

### 升级任务（L2 → L3）
- [ ] 通关《保姆级教程》4-13 章（网络服务/AWS/容器/自动化/监控）
- [ ] 用 IaC（Terraform）重做你手动做过的所有部署——**手→代码是质变**
- [ ] 开始"服务闪卡"训练（《00 总纲》训练法 1），50 个核心服务打到条件反射
- [ ] 至少在两个平台（如 AWS + 阿里云）完成同一个部署——学会"脱离平台看概念"
- [ ] 每月读一篇云厂商故障复盘（Postmortem）并写 200 字心得

> 预计时间：3-6 个月

---

## L3 · 设计者（"能白手起家"）

### 典型特征
- 给需求能设计架构并**解释每个决定的原因**
- 开始有自己的"技术品味"（"这种需求我不推荐用 XX"）
- 但面对复杂权衡（成本 vs 进度 vs 安全）时还需要参考意见

### 自测题
1. **白板测试**：20 分钟内为"一个日活 10 万的在线考试系统"画出完整架构，并说明：数据放哪、怎么抗峰值、怎么防作弊流量、成本大概多少
2. 拿任意一个你熟悉的 App，逆向拆解它的架构并给出证据（如通过响应头判断 CDN、通过接口延迟判断缓存）
3. 给你一个"月成本 5 万美元"的架构图，指出至少 3 处浪费和优化方案
4. 设计一个"两地三中心"的容灾方案，说清 RTO/RPO 与成本的关系
5. 把你上周画的架构图重新审视：找出 3 处当时没发现的问题

### 升级任务（L3 → L4）
- [ ] 完成本系列《04 架构模式手册》全部 30 个模式的条件反射训练
- [ ] 用 Well-Architected 六支柱对自己做过的方案做一次完整评审（写出评审报告）
- [ ] 建立"设计文档"习惯：每周一篇 500 字（背景/方案/取舍/成本/风险）
- [ ] 参加至少 3 次"架构评审"（公司/社区/比赛的都行），既评别人也被评
- [ ] 系统学习一门"相邻学科"：分布式系统原理 / 数据库内核 / 网络协议（选一深挖）
- [ ] 通过一个硬核认证检验自己（AWS SAP / CKA / 同等级别）

> 预计时间：6-18 个月，此级开始分化（有人快有人慢，取决于输出量）

---

## L4 · 架构师（"能对抗真实世界的复杂性"）

### 典型特征
- 能在多方约束（预算、人力、合规、遗留系统）中给出**可落地**的方案
- 能预判方案的失败模式，提前布防
- 别人拿难题找你，你给的不是答案，是"三条路及各自代价"

### 自测题
1. 给你一个"银行核心系统上云"的命题：写出 6 个月迁移路线图（阶段/里程碑/风险/止损点）
2. 设计一个系统，要求：全球部署、单区域故障不停服、数据合规（本地存储）、成本可控——给出方案和取舍理由
3. 你设计的系统上线后开始"随机超时"，给出你的完整排查计划（排查路径 + 每步的依据）
4. 给一个你不熟悉的行业（如"冷链物流"）设计 IoT+云方案，两周内完成（考察快速学习能力）
5. 复盘一个失败的技术决策（你自己的或公开的），分析决策链条哪里错了

### 升级任务（L4 → L5）
- [ ] 主导一个真实系统的"从 0 到 1"或"从 1 到 100"（工作/开源/创业均可）
- [ ] 建立个人知识体系（把散落的经验变成可传授的方法论——本系列就是范例）
- [ ] 每年深挖一个"没人教的前沿"（如边缘计算/机密计算/量子/Agent 工程），产出公开内容
- [ ] 培养"判断力"：跟踪新兴技术，练习"这个技术 3 年后会怎样"的预判并记录（事后对照）
- [ ] 开始教学：带徒弟/写专栏/做分享——**教是最好的学**

> 预计时间：2-5 年，且需要运气（遇到好项目）与刻意选择（主动接硬骨头）

---

## L5 · 母语者 / 大师（"创造语言的人"）

### 特征
- 面对未见过的领域问题，能**从第一性原理推导**出解法
- 技术判断被行业验证（你选的方向后来成为主流）
- 别人用你的框架、你的文章、你的工具思考问题
- 对技术有"审美"：能分辨优雅与丑陋的方案

### 他们共同的习惯（观察大师们得出的规律）
1. **永远在舒适区边缘**：每半年主动换一个"不会的东西"啃
2. **输出密度极高**：写书、开源、演讲、内部文档——输出是他们思考的方式
3. **跨学科连接**：从生物学看自愈系统，从经济学看资源调度，从城市规划看微服务
4. **尊重第一性原理**：不背结论，只信推导
5. **时间的朋友**：代表作都是 5-10 年持续投入的产物

**如何走向 L5？没有标准路径，但可以确定的是：** 你必须先扎实地成为一个领域的 L4，然后持续输出、持续预测、持续被现实纠正——直到某天你发现，是别人在追你的文章学了。
