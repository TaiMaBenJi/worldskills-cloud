# 计算机母语之路 02 · 24 个月整合计划：五线并行的每一天

> 本篇是整套体系的"时刻表"。读完《01 拆解地图》后，从这里开始执行。
> 设计前提：**每天 3-4 小时**（早 1h + 晚 2-3h 的经典结构）。只有 1-2 小时/天？看文末《弹性调整指南》——时间可以拉长，结构不许改变。

| 阶段 | 月份 | 主题 | 主产出 |
|------|------|------|--------|

## 每周课表模板（阶段 1-4 通用骨架）

### 工作日（3-4 小时版）
| 时段 | 时长 | 内容 | 说明 |
|------|------|------|------|
| 早晨 | 45-60 min | **C 训练**（读书+写码各半） | 脑子最清醒时练"语言肌肉" |
| 晚上① | 60-90 min | **主线项目**（系统要素/自己的编译器） | 深度工作块，手机放另一个房间 |
| 晚上② | 45-60 min | **理论/认知线**（龙书/鲸书/思考快与慢） | 读+做笔记+手推 |
| 睡前 | 10 min | **闪卡+日记** | 今天的直觉卡 ×3 + 3 行学习日志 |

### 周末（每天 4-6 小时）
| 动作 | 时长 | 说明 |
|------|------|------|
| 大块项目时间 | 3-4h | 攻克本周最难的硬骨头（项目里程碑） |
| 周复盘 | 30 min | 三问：最强收获/最大卡点/下周砍什么 |
| 讲解输出 | 30 min | 给某人讲本周最重要的一个概念 |
| 补债时间 | 1h | 补上工作日欠下的内容（如有） |

**每周固定节奏**：周一~周五推进，周六攻坚，周日复盘+输出+休息半天。**休息是计划的一部分，不是计划的敌人。**

## 阶段 0 · 点火（第 1 个月）

### 目标
- 建立全套"操作系统"：认知框架 + 工具链 + 习惯
- C 语法速通（有编程基础者快进，无基础者放慢到 6 周）

### 每日任务
| 线 | 内容 |
|----|------|
| C | 《C Primer Plus》1-6 章：变量/运算符/控制流/函数基础，每天 1 章 + 课后 3 题 |
| 系统要素 | 读第 0-1 章，装好官方工具链，完成**项目 1**（布尔门） |
| 认知 | 《思考快与慢》第一部分（系统 1/2），读 + 建立 10 张"偏见卡" |
| 元任务 | 配好：Git 仓库（记录所有代码）、学习打卡表、闪卡系统（Anki/备忘录） |

### 验收（月底）
- [ ] 项目 1 通过官方测试（门电路全部验证）
- [ ] C 能独立写出：加减乘除计算器 + 猜数字游戏 + 字符串反转
- [ ] 能用自己的话解释系统 1/2，并说出自己的 3 个学习坏习惯

## 阶段 1 · 硬件筑基（2-6 月，5 个月）

### 目标
从 NAND 门造到 CPU（系统要素项目 1-5），C 的指针/内存肌肉成型。

### 每周排程（五线并行）
| 线 | 每周任务 | 里程碑 |
|----|----------|--------|
| 系统要素 | **每周推进约 1 个项目**：项目 2（ALU）→3（寄存器/内存）→4（机器语言）→5（CPU） | 项目 5 完成 = 你造出了一台计算机！ |
| C | 指针专题月 ×2：第 7-11 章精读+微项目（动态数组库等）；然后字符串/结构体/内存管理 | 手写 malloc 简化版 |
| 理论预热 | 不读龙书。只做：跟着项目 4-5 写 Hack 汇编小程序（冒泡排序、画屏幕） | 汇编不再可怕 |
| 认知 | 每月重读《思考快与慢》划线部分 1 小时；应用"峰终定律"设计每周学习结尾 | 月记：我的系统性改进 |
| 输出 | 每两周 1 次讲解（"我造了 ALU"）；每月 1 张正式架构图（把 Hack CPU 画成图） | 5 张图 + 10 次讲解 |

### 阶段 1 亮点任务（别跳过）
1. **项目 5 完成后：全程录像或拍照记录**，写一篇《我用 5 个月造了台计算机》发出去——这会是你的第一次"大输出"
2. **用 C 写一个 Hack 汇编模拟器**（把项目 4 的汇编跑起来）——把 C 和系统要素提前咬合
3. 每周一次"盲写测试"：合上书，徒手写出一个门电路的 HDL（系统 1 化训练）

### 验收（第 6 月底）
- [ ] 项目 1-5 全过官方测试
- [ ] 能徒手画出 Hack CPU 数据通路 + 解释每条控制位
- [ ] C：指针/内存题（20 道混合练习）正确率 90%+；无泄漏项目 3 个
- [ ] 龙书第 1 章翻过一遍（只有这一章）

## 阶段 2 · 软件纵深（7-12 月，6 个月）

### 目标
把"自己的计算机"变得可编程：汇编器（项目 6）→ VM（项目 7-8）→ 高级语言（项目 9），同时 C 进入工程级。

### 每周排程
| 线 | 每周任务 |
|----|----------|
| 系统要素 | 项目 6（汇编器，用你熟悉的语言写，**强烈建议用 C**）→ 项目 7-8（VM 实现，**最难的部分，给自己留足时间**）→ 项目 9（用 Jack 写游戏，熟悉目标语言） |
| C | 内存管理深化（第 12 章）+ 结构体/联合体 + 文件 IO；**项目：写一个简易 shell（fork/exec）** 和 **HTTP 静态服务器** |
| 理论 | 开始读**龙书第 2-3 章**（词法/语法分析）：先读一遍，不强求全懂——**项目 6-8 的经历是理解它的钥匙**；每月手推 1 个 DFA |
| 认知 | 每月重读 + 用"认知放松"原理优化自己的学习环境（固定书桌、番茄钟、难度调节） |
| 输出 | 每月 1 篇技术笔记（"为什么汇编器要两遍扫描"、"VM 的栈帧设计"） |

### 关键提醒
- **项目 7-8（VM）是全课程最陡峭的一段**：函数调用、栈帧、指针别名、静态/动态绑定——卡 3 天很正常。用"最小复现"法：把失败的指令序列缩到 5 行以内再调试
- **建议同时开始《Crafting Interpreters》第一部分**（树遍历解释器）：和项目 9-10 是完美的互相印证
- 每月一次"回头重做"：用今天的能力，重看第 1 个月写的 C 代码，找 5 个毛病并修复

### 验收（第 12 月底）
- [ ] 项目 6-9 全过（能用自己写的汇编器/VM 跑项目 9 的 Jack 游戏）
- [ ] C：做出 shell + HTTP 服务器两个真项目
- [ ] 龙书 2-3 章读完 + 手推笔记 ≥6 份
- [ ] Crafting Interpreters 第一部分完成（能跑一个脚本语言）

## 阶段 3 · 编译器炼成（13-18 月，6 个月）

### 目标
**核心六个月**：亲手写出编译器（系统要素项目 10-11）→ OS（项目 12）→ 龙书攻坚。

### 每周排程
| 线 | 每周任务 |
|----|----------|
| 系统要素 | 项目 10（编译器 I：语法分析器）→ 项目 11（编译器 II：代码生成）→ 项目 12（OS：内存/字符串/屏幕/键盘/数学库） |
| 龙书 | **精读期**：第 4 章（语法分析）→ 第 5-6 章（语法制导翻译+中间代码）→ 第 7-8 章（运行时+代码生成）。每章手推 + 对照自己的编译器项目 |
| C | 项目实践：给你的编译器写单元测试框架；读一段真实源码（如 Lua 的 vm.c / jq 的源码） |
| Crafting Interpreters | 第二部分（字节码 VM）推进 |
| 认知 | 每月重读 + "峰终"设计里程碑奖励（项目 11 完成 = 大奖励） |
| 输出 | **项目 11 完成时：写一篇长文《我从零写了一个编译器》**（一定会火）；每月 1 篇技术笔记 |

### 巅峰时刻预告
**项目 11 的最后一刻**：你用自己写的编译器，把 Jack 语言编译成 VM 代码，用你写的 VM 执行，跑在你造的 CPU 上，在你写的 OS 上显示出来——**从 NAND 到游戏，全是你自己造的。** 这就是本体系"母语化"的最高浓度体验。把它录下来。

### 验收（第 18 月底）
- [ ] 项目 10-12 全过（含 OS 测试）
- [ ] 龙书第 1-8 章 + 手推题完成
- [ ] Crafting Interpreters 全完成（两个解释器）
- [ ] 用一句话能向任何人解释："编译器就是把文本变成行为的翻译官，它分六步……"

## 阶段 4 · 深度与工业（19-24 月，6 个月）

### 目标
从"会写编译器"到"懂优化器"：鲸书主线 + LLVM 对照 + 毕业项目。

### 每周排程
| 线 | 每周任务 |
|----|----------|
| 鲸书 | 主线四章：数据流分析 → SSA → 循环优化 → 调度/寄存器分配。**每章配一个复现实验**（给你的编译器加一个真优化 pass） |
| LLVM | 每学完一章鲸书，读对应 LLVM pass 源码 200 行 + 写笔记（mem2reg / licm / GVN…） |
| 编译项目进阶 | 你的编译器升级之路：加类型系统 → 加 3 个优化 pass → 测量性能提升（做出前后对比数据） |
| C | 读工业 C 源码（Redis / SQLite 任选），每周 300 行 + 笔记 |
| 认知 | 合上《思考快与慢》，写出你自己的《学习操作手册》（这一年的所有应用总结） |
| 毕业输出 | 系列长文/视频：《24 个月，从 NAND 到编译器》全程复盘 |

### 毕业项目（二选一或都做）
**A. "我的编译器 v2"**：重写一遍你的编译器（这次直接写真实的子集语言，如 C 子集），加上完整的优化管线，输出性能对比报告
**B. 连接你的云计算之路**：写一个"云端任务语言"——一个 DSL，编译成容器编排配置或云函数（**把你两条学习线的产出合并**）

### 验收（第 24 月底 = 总验收）
- [ ] 鲸书主线四章 + 4 个复现实验
- [ ] 能读 LLVM 优化 pass 源码并讲原理
- [ ] 毕业项目完成并公开
- [ ] 完整自测：本系列《00 总纲》的 4 条硬核验收标准逐条通过
- [ ] 你有了自己的《学习操作手册》+ 两年的打卡记录 + 一堆可展示的作品

## 弹性调整指南（时间不够时怎么改）

### 只有 1-2 小时/天（总时长变 4 年）
- 保持五线结构，但每天只跑 2 条线（轮换）：周一三五=C+主线，周二四=理论+认知，周末补漏
- 铁律不变：动手 ≥ 阅读；每天不断线（最低 5 分钟版本：闪卡 + 日记）
- 阶段时长全部 ×2，但**每次坐下必须有一段"手指动"的时间**

### 中途加入不了这么多书怎么办
- 优先级排序（砍书的顺序）：鲸书 > Crafting Interpreters > 龙书后半 > 系统要素（最后砍）
- 绝对不能砍的：**系统要素 + C + 思考快与慢**——这三样是"母语"的最小组合

### 卡住了/想放弃时的急救包
1. 打开《03 认知引擎》做一次"系统 1/2 诊断"——90% 的放弃是认知问题不是能力问题
2. 回看你的打卡表和已完成项目——**你已经走了这么远，这是事实，不是情绪**
3. 把当前任务切小：不是"完成项目 8"，而是"让 pop 指令跑通一个用例"
4. 给自己放 3 天假（真的休息），第 4 天用"基础版"回归
