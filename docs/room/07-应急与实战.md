# 机房管理 · 07 应急与实战手册

> 前面六篇是"平时"；这一篇是"战时"。
> 所有预案的目标只有一个：**当告警响起时，你的第一动作是唯一且正确的。**

---

## 7.1 应急体系（先有体系，再有动作）

### 预案分级

| 级别 | 定义 | 响应 |
|---|---|---|
| 黄 | 单点异常，不影响业务 | 当班处理，记录 |
| 橙 | 冗余丧失/局部影响 | 负责人到位，准备预案 |
| 红 | 业务中断/安全威胁 | 全员响应，上报领导，启动对外沟通 |

### 组织与分工（哪怕只有 3 个人也要分）

- **指挥**：决策"保谁舍谁"、对外发声（首选从未参与操作的人——避免救火者指挥）
- **操作**：执行处置（体力与命令）
- **记录/联络**：记时间线、打电话、盯监控（这个人常被忽略，但复盘全靠他）

### 一张纸的预案（每张场景卡都是这个结构）

```
现象描述 → 第一动作（止损）→ 后续流程 → 红线（千万别做的事）→ 升级条件
```

## 7.2 故障树：从现象到根因

**方法**：现象不是原因。把现象当"树的顶"，往下问"什么会导致它"：

```
现象：某业务无法访问
├── 网络层？  ping 网关 / 看交换机 / 看链路
├── 主机层？  进程在吗 / 资源满吗 / 负载异常吗
├── 服务层？  端口监听吗 / 日志报什么错
├── 数据层？  存储可用吗 / 连接数满吗
└── 以上都正常 → 上游（DNS/证书/防火墙策略/运营商）
```

**三个通用模型**：
1. **分层排除**（自下而上或自上而下，逐层验证）
2. **变更关联**（"最近动过什么？"——80% 的故障与最近变更相关）
3. **替换验证**（换端口/换机器/换线路——复杂问题用"换"来二分）

## 7.3 场景处置卡（20 张）

> 建议打印出来，放在机房值班位。**每季度随机抽 3 张做桌面推演。**

### 卡 01 · 市电一路中断
**现象**：动环告"市电 A 路中断"。
**第一步**：确认 UPS 工作状态（正常应无缝带载）；看负载率与电池续航估算。
**接着**：联系供电部门确认范围/预计恢复；通知负责人；核对 B 路是否正常。
**千万别**：盲目操作 UPS 面板；未确认续航前继续加负载。
**升级**：B 路异常 / 续航 <15 分钟 / 油机启动失败。

### 卡 02 · 双路市电全断
**现象**：两路全断，UPS 转电池。
**第一步**：**立刻算续航**（负载 ÷ 电池容量），启动油机（如有）。
**接着**：按预案有序关闭非关键设备（每关机一台延长续航若干分钟）；保核心业务到最后。
**千万别**：等电池快耗尽才决策——要在续航剩 1/3 前完成全部关键决策。
**升级**：油机 30 分钟内启动不了 → 全面准备有序全关。

### 卡 03 · UPS 故障 / 过载告警
**现象**：UPS 报过载/旁路/故障。
**第一步**：确认是否在旁路运行（市电直供，此时无保护）；立即减少负载（迁移非关键设备）。
**接着**：联系 UPS 维保；评估市电直供期间的风险等级。
**千万别**：继续加载；自行拆机检修。
**升级**：UPS 宕机风险高 → 按"双路全断"预案准备。

### 卡 04 · 电池组告警
**现象**：电池电压异常/内阻告警/鼓包渗液。
**第一步**：确认告警种类；若鼓包渗液 → 隔离区域、通风、禁烟禁火（铅酸漏液有腐蚀性，锂电更危险）。
**接着**：安排专业检测更换；评估"当前无后备"状态下的风险（通知相关负责人）。
**千万别**：触碰渗液；搬动鼓包电池；继续满负荷运行。

### 卡 05 · 空调故障（一台）
**现象**：单台精密空调停机告警。
**第一步**：确认其余空调带载状态；打开备用机。
**接着**：盯温度曲线（每 10 分钟记录）；准备移动空调；评估降载方案。
**千万别**：开窗/开门吹走廊风（破坏环境且引入灰尘）——除非温度失控的紧急降温。

### 卡 06 · 温度飙升（>35°C）
**现象**：冷通道温度持续上升且无法抑制。
**第一步**：**主动降载**（有序关闭非关键设备）——比等设备热宕机安全 100 倍。
**接着**：移动空调/风扇辅助；持续监测；准备进一步降载。
**千万别**：心存侥幸——40°C 以上硬件会自我保护宕机，被动宕机比主动关机危险得多（RAID 重建/数据损坏风险）。

### 卡 07 · 漏水
**现象**：漏水检测告警 / 地面见水。
**第一步**：定位水源（空调冷凝水/机房上方管道/消防管）；**远离电气区**。
**接着**：通知电工/物业关闭相关水阀（水+电=致命）；吸水/排水；抬高受威胁设备。
**千万别**：湿手碰电；盲目进入积水区；用水冲任何设备区。
**升级**：水源不明或量大 → 全区域断电评估。

### 卡 08 · 火警报警（未确认）
**现象**：烟感报警，声光启动，未确认明火。
**第一步**：**人先撤到安全位**再看——确认是误报还是初期火情（通过监控/窗户/他人反馈）。
**接着**：确认火情 → 全员撤离+报火警；误报 → 记录并复位系统，查找误报原因。
**千万别**：独自深入查看；为"确认一下"耽误撤离时机。

### 卡 09 · 火灾（确认）
**现象**：明火/大量烟。
**第一步**：**撤离！报火警 119！** 气灭喷放前必须确保无人。
**接着**：外部灭火；保护/抢救顺序：人 > 数据介质（如果顺手且安全）> 设备。
**千万别**：贪恋设备；返回取物。

### 卡 10 · 单盘故障
**现象**：服务器告警/RAID 界面显示一块盘 Degraded。
**第一步**：定位盘位（LED + 管理界面双确认）；确认备份状态。
**接着**：按热插拔流程换盘；盯重建进度；重建期降低该机负载。
**千万别**：不确认盘位就拔盘（拔错盘=二次事故）。

### 卡 11 · 双盘故障（RAID 崩溃边缘）
**现象**：RAID5 已坏一块，第二块告警/掉线。
**第一步**：**停止一切写操作**；立即联系存储/服务器厂商支持。
**接着**：优先备份可读数据；准备从备份恢复的完整方案。
**千万别**：自己乱试重建（错误操作可能让阵列彻底无法恢复）；寄希望于"再撑一撑"。

### 卡 12 · 服务器宕机（不明原因）
**现象**：监控失联，带外也进不去。
**第一步**：带外管理查电源/硬件状态（带外进得去=系统问题；进不去=硬件/供电问题）。
**接着**：看 SEL 硬件日志；尝试带外重启；联系维保。
**千万别**：直接按电源键硬重启（先收集证据：屏幕/日志——重启会丢现场）。

### 卡 13 · 网络全断
**现象**：机房所有设备失联/外网断。
**第一步**：分层排查——本机 → 接入交换机 → 汇聚 → 核心 → 出口。
**接着**：看交换机面板/指示灯、Console 口登录；联系运营商确认线路。
**千万别**：一上来重启核心设备（先在非核心上验证假设）。

### 卡 14 · 疑似物理入侵
**现象**：门禁异常记录/视频发现可疑人员。
**第一步**：确认人员身份（联系登记部门）；已离开 → 查证损失并报警。
**接着**：保全证据（视频/门禁记录）；排查设备是否被动过（序列号核对）。
**千万别**：与可疑人员单独冲突（人身安全第一）。

### 卡 15 · 勒索病毒（IT+物理联动）
**现象**：业务系统文件被加密，出现勒索信。
**第一步**：**断网隔离**（拔网线/关端口）——物理层动作也是机房管理者的活。
**接着**：保留现场；上报；**立即核查备份的完整性**（勒索病毒会加密备份！检查异地/离线备份）。
**千万别**：格式化重装（证据没了，可能备份也没了）；付赎金。

### 卡 16 · 断电恢复后（开机风暴）
**现象**：市电恢复，大量设备上电。
**第一步**：**分批上电**（先网络与监控，再核心业务，最后批量设备）——防"开机电流冲击"与二次断电。
**接着**：逐批验证；关注 UPS 充电状态与电池温度；监控告警峰值。
**千万别**：一次性全部上电。

### 卡 17 · 空调冷凝水溢出
**现象**：空调附近积水/地板下湿报警。
**第一步**：停该台空调（水阀）；吸水处理和干燥。
**接着**：检查排水管是否堵塞（常见根因）；恢复前确认干燥和绝缘检查。
**千万别**：水未干就恢复供电。

### 卡 18 · 极端天气预警（台风/暴雨/地震）
**现象**：气象预警发布。
**第一步**：提前行动——检查窗户/防水/排水；设备防倾倒固定；备电检查。
**接着**：安排值班加强；准备停电预案；重要数据提前备份。
**千万别**：预警后才开始准备。

### 卡 19 · 门禁失效（人员被困/无法进入）
**现象**：门禁系统宕机，人员被困或无法进入。
**第一步**：确认人员安全（被困优先解救——机械应急开关/破拆）。
**接着**：恢复门禁；临时改为人工登记值守。
**千万别**：为进机房暴力破门（评估安全后走应急流程）。

### 卡 20 · 监控全瞎（动环失效）
**现象**：动环监控平台宕机/传感器批量失联。
**第一步**：**派人现场巡检**（回到人工模式——宁可人跑腿，不能无监控裸奔）。
**接着**：排查平台故障（网络/主机/采集器）；恢复后核对"失明期间"的事件。
**千万别**：假装没事继续无人值守。

## 7.4 复盘方法论（比应急本身更重要）

### 事故复盘模板（48 小时内完成）

```
【事故报告】标题：XXXX年X月X日 XX 故障

1. 事实时间线（精确到分钟）
   14:02 告警触发……
   14:05 值班响应……
   （只写事实，不写推测）

2. 影响面
   影响了什么业务/多少用户/多长时间

3. 根因分析（5 Why）
   为什么断？→ 因为……
   为什么没提前发现？→ 因为……
   （问到"制度/体系"层为止，别停在"某人手滑"）

4. 处置评价
   做对的：……（要具体）
   做错的/可改进的：……

5. 改进项（每项有 Owner + 期限）
   - [ ] 增加 XX 监控  @张三  9/30 前
   - [ ] 修改 XX 流程  @李四  9/25 前
```

**复盘三原则**：对事不对人（否则以后没人说真话）；追体系不追个人失误（人会犯错，体系要防错）；改进项必须闭环（下次复盘先检查上次的改进项）。

## 7.5 演练设计（不做演练的预案 = 废纸）

### 桌面推演（零成本，每季度一次）

1. 选一张场景卡（如：卡 02 双路全断）
2. 主持人念现象，参与人口述"我的第一动作、第二动作……"
3. 计时：看决策链条有多少空白点；把空白点变成新的演练/整改项
4. 记录：谁在场/推演了哪张卡/发现了什么

### 单点演练（低成本，每半年）

- 拔掉一路电源看 UPS 切换（在业务低峰期）
- 关闭一台空调看温度响应
- 模拟一块盘"离线"看告警链路

### 全流程演练（年度，提前公告）

- 完整走一遍：告警 → 响应 → 分工 → 处置 → 沟通 → 恢复 → 复盘
- 邀请"外人"观察（领导/同事）——压力测试沟通与协作

## 7.6 自测

1. 应急响应时"记录员"的作用是什么？（记时间线+联络+盯监控——复盘的全部依据来自这个人，且他是唯一"不参与操作"的清醒视角）
2. 为什么"主动关机"比"等宕机"安全？（热宕机可能损坏数据/触发危险重建；主动关机可控、有顺序、可恢复）
3. 燃油发电机的作用是"替代 UPS"还是"延长续航"？（延长/接棒——UPS 撑 10-30 分钟是为了等油机启动并带载）
4. 复盘为什么不能停在"某员工操作失误"？（因为人会犯错是既定事实，体系必须假设人会犯错并防错——停在个人=没有改进）

**动手练习**：pick 三张场景卡，为自己所在环境写"本地化版本"（填上真实的电话、真实的位置、真实的设备名）。
