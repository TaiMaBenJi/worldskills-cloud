## 4.1 PXE 工业级（从"能装"到"可运营"）

### 4.1.1 完整架构（正规军版本）

```
┌─────────────────────────── 装机服务器（Linux） ───────────────────────────┐
│  dnsmasq（DHCP + TFTP + PXE 引导）                                        │
│  HTTP/NFS（发行版镜像 + 应答文件 + 软件仓库）                              │
│  引导菜单（多发行版/多角色可选）                                            │
└──────────────────────────────────────────────────────────────────────────┘
        │① DHCP 响应（IP + next-server + bootfile）
        ▼
   裸机开机（PXE ROM）
        │② TFTP 拉引导程序（pxelinux.0 / grubx64.efi / snponly.efi）
        ▼
   引导菜单（选 Ubuntu 24.04 服务器 / CentOS / 维修模式…）
        │③ 加载内核 + initrd（TFTP/HTTP）
        ▼
   自动安装（读取应答文件：分区/账号/软件包/网络）
        │④ 首次启动脚本（注册监控、拉取配置、登记资产）
        ▼
   交付完成（0 人工介入）
```

### 4.1.2 BIOS 与 UEFI 两条引导链

| 环境 | 引导文件 | 特点 |
|---|---|---|
| Legacy BIOS | `pxelinux.0` + `ldlinux.c32` | 老机器 |
| UEFI | `grubx64.efi` / `shimx64.efi` + grub.cfg | 现代机器（**新采购全部 UEFI**） |

实操坑点：
- UEFI 下 `dhcp-boot` 要指向 `.efi` 文件（或做架构判断 `dhcp-match` 给不同文件）
- Secure Boot 开启时需要用**签过名的 shim** 或先在 BIOS 里暂时关闭

### 4.1.3 Kickstart 应答文件（红帽系）核心段

```kickstart
#version=RHEL9
text
lang zh_CN.UTF-8
keyboard us
timezone Asia/Shanghai --utc
network --bootproto=dhcp --hostname=srv-template

# 分区方案（按角色模板化）
ignoredisk --only-use=sda
clearpart --all --initlabel
part /boot --fstype=xfs --size=1024
part / --fstype=xfs --size=51200
part /data --fstype=xfs --grow --size=10240
part swap --size=8192

rootpw --iscrypted $6$.....       # 密码用哈希，不写明文
user --name=ops --groups=wheel

%packages
@^minimal-environment
vim, curl, chrony, zabbix-agent
%end

%post
# 首次启动自动动作：注册、加固、拉配置
systemctl enable chronyd
curl -s http://pxe.local/post-install.sh | sh
%end
```

> Debian/Ubuntu 系对应 **preseed / autoinstall（cloud-init）**；Alpine 用 **answerfile**。逻辑同构：分区 + 账号 + 包 + 脚本。

### 4.1.4 装机故障树（卡住时逐层查）

```
开机没进 PXE？
  ├─ BIOS 启动顺序没设网络启动
  └─ 网卡 PXE ROM 被禁用
DHCP 拿到了但卡在 TFTP？
  ├─ dhcp-boot 文件名错 / 路径不对
  └─ TFTP 服务没起 / 防火墙挡了 UDP 69
TFTP 拿到引导，卡在加载内核？
  ├─ 内核/initrd 路径错（HTTP 路径检查）
  └─ UEFI vs BIOS 引导文件不匹配
安装跑起来但应答文件没生效？
  ├─ ks 文件 URL 错 / 权限 404
  └─ 内核命令行里没带 ks= 参数
```

## 4.2 装机后自动化（装完不是结束）

**"首次启动三件事"**（写进自动流程）：

1. **注册资产**：主机名/序列号/配置 → 自动写入 CMDB（哪怕是一张表）
2. **接入监控**：agent 上线，出现"这台机器"的曲线
3. **拉取配置**：Ansible/Puppet 接管，机器进入"声明式管理"状态

**工厂式交付的定义**：一台机器从通电到"拿到手上就能用"，**零人工步骤**——这是 L3 的标志性能力。

## 4.3 镜像与克隆体系

### 母盘制作标准（做一次，用一年）

1. 干净系统 + 标准分区 + 必要驱动/工具（最小化原则）
2. 系统清理：临时文件、日志、历史；Windows 还要 **sysprep**（重置 SID/激活状态）
3. **重置机器身份**：Linux 清 `/etc/machine-id`、SSH host key、网卡配置缓存；Windows 用 sysprep /generalize
4. 打快照/导镜像 → 命名规范：`base-ubuntu2404-v3.2-20260918.qcow2`
5. **版本管理**：镜像也是代码——变更留记录，旧版保留 N-1 份

### Clonezilla 工作流（适合硬件一致的教室/机房）

```
母机制作 → 母机启动 Clonezilla → 保存镜像到存储（NFS/USB）
→ 目标机网络启动 Clonezilla → 恢复镜像 → 改主机名/IP（脚本化）
```

> 与 PXE 的分工：**异构环境用 PXE（逐台装），同构批量用克隆（复制）**。学校机房大批同型号电脑 → 克隆更快。

## 4.4 桌面场景：还原 / VDI / 教学环境

### 三个方案对比（学校机房决策表）

| 维度 | 传统 PC + 还原 | VDI 云桌面 | 混合（胖终端+集中管理） |
|---|---|---|---|
| 前期成本 | 低 | 高（服务器+存储+许可） | 中 |
| 后续运维 | 逐台维护 | **集中维护，改一次全生效** | 半集中 |
| 性能体验 | 本地满血 | 依赖网络与并发（渲染/多媒体弱） | 接近本地 |
| 数据安全 | 数据在终端 | **数据不出机房** | 混合 |
| 适合场景 | 普通上机课 | 考试/实验/多终端一致性 | 高性能课程 |
| 断电影响 | 单机 | 全教室停课（集中风险） | 部分 |

### VDI 架构一分钟

```
瘦客户端/胖终端 ──局域网── VDI 服务器（虚机池）── 存储（共享镜像）
                        │
                  桌面协议（RDP/SPICE 等）
```
关键指标：并发密度（一台服务器带多少桌面）、启动风暴（全班同时开机——用链接克隆/缓存分压）、外设兼容性（U 盘/打印/教学软件）。

### 还原方案选型要点

- 还原粒度：每次重启 vs 按策略
- 增量保存：学生作业要能"穿越还原"（存网络盘/个人云盘）
- 管理端：能遥控解锁、批量更新、远程协助
- **考试保障模式**：考试期间可切"完全保护+锁定"

### 教学软件批量管理

- 统一安装包 + 静默安装参数（`setup.exe /S` 类）批量推送
- 版本一致性检查（上课前脚本比对版本号）
- 冲突管理：先装底层（保护系统）→ 再装应用 → 最后装还原"冻结"

## 4.5 自动化的哲学（比工具重要）

1. **幂等**：跑一遍和跑十遍结果一样（脚本要能重复执行）。
2. **可重复**：任何人、任何时间执行都是同样结果（无手工前提）。
3. **可审计**：谁改了什么、什么时候、结果如何（日志/版本管理）。
4. **最小惊讶**：脚本行为可预测，不用"聪明"的隐藏逻辑。
5. **失败要响**：错误必须让人知道（退出码/告警），静默失败是原罪。

**从脚本到平台的路线**：
```
手工 → 单机脚本 → 带参数的脚本库 → 批量执行（Ansible）→ 声明式平台（GitOps 风格）
```
每一步都用上一阶段验证过的东西；**不要跳过**——没有脚本经验的团队直接上平台，等于不会走就学跑。

**装机流水线终局示意**：
```
PXE 装机 → cloud-init 初始化 → Ansible 定型 → 监控上线 → 备份注册 → CMDB 登记 → 持续合规检查
```
一条命令，十个新节点全部就绪——这就是"装一百台"的正确姿势。

## 4.6 自测与练习

1. UEFI 环境下 dhcp-boot 指向 `pxelinux.0` 会怎样？（引导失败——UEFI 需要 `.efi` 引导文件）
2. 应答文件里 root 密码为什么用 `$6$` 哈希？（明文密码会出现在 HTTP 服务器日志/进程列表里，明文即泄露）
3. 克隆出的 30 台机器"长得一模一样"，上电后必须处理什么？（主机名/IP/机器 ID/SSH key——否则网络冲突与管理混乱）
4. VDI 最怕的"启动风暴"怎么解？（链接克隆分摊存储 IO + 开机限流/错峰 + 缓存预热）
5. 自动化脚本"幂等"为什么是底线？（无人值守场景会反复执行；不幂等 = 每次执行都在赌）

**动手练习**：
- 在训练场（`wsarena task 6`）完成 PXE 服务端配置；
