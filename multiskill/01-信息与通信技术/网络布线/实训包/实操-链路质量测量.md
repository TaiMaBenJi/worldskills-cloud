# 🔬 实操 · 链路质量测量（WSL 模拟，10 分）

> 真实布线用认证仪表测**串扰/回损/插损**；但链路质量的三个体感指标——**延迟、抖动、丢包**——可以用软件在你自己的 Ubuntu 练习机里"制造"出来并测量。这个实验让你像排障工程师一样读取链路指标。

## ⚠️ 安全须知（必读）

- 本实验**只允许操作 `lo`（本地回环）网卡**，绝不动 `eth0`，否则可能断网
- 所有命令在 WSL（Ubuntu-22.04）里以 root 执行：终端输 `wsl` 进入
- 实验结束必须执行"第 6 步清理"，恢复链路

---

## 第 1 步 · 装测量工具

```bash
sudo apt install -y iperf3
```

## 第 2 步 · 测"健康链路"基线

终端 A（保持运行）：

```bash
iperf3 -s
```

终端 B：

```bash
ping -c 10 127.0.0.1 | tail -3          # 记录 rtt avg
iperf3 -c 127.0.0.1 -t 5 | tail -5      # 记录带宽 sender/receiver
```

✅ 记录：基线延迟 ≈ 0.02~0.05ms，带宽 ≈ 数十 Gbps（回环很快属正常）。

## 第 3 步 · 制造"长距离链路"：+30ms 延迟

```bash
tc qdisc add dev lo root netem delay 30ms
ping -c 5 127.0.0.1 | tail -2
```

📌 **观察点**：rtt ≈ **60ms**（不是 30！）—— 因为延迟在**往返两个方向各加一次**。这就是"链路延迟按单向算、仪表按往返测"的体感。

## 第 4 步 · 制造"劣质链路"：加 2% 丢包 + 抖动

```bash
tc qdisc change dev lo root netem delay 30ms 10ms loss 2%
ping -c 100 127.0.0.1 | tail -3          # 看丢包率：目标 2%，小样本在 1%~4% 波动属正常
iperf3 -c 127.0.0.1 -t 5 | tail -5      # 看吞吐较基线下降多少
```

📌 **观察点**：
- ping 的 loss ≈ 2%
- iperf3 吞吐比基线**大幅下降**，可能出现 `retransmits`（重传）计数 —— TCP 靠重传兜底丢包，代价是速度
- 对照布线：**串绕/噪声 → 误码 → 丢包 → 重传 → 用户感知"网慢"**。认证测试把串扰提前测出来，就是在避免这种"能通但难用"的链路

## 第 5 步 · 抖动体感（可选加分）

```bash
tc qdisc change dev lo root netem delay 25ms 15ms
ping -c 20 127.0.0.1 | tail -2          # 看 mdev（标准差）明显变大
```

📌 mdev = 抖动的量化指标。视频会议卡顿就是它造成的。

## 第 6 步 · 清理（必做！）

```bash
tc qdisc del dev lo root
tc qdisc show dev lo                    # 应显示 noqueue，即恢复
ping -c 3 127.0.0.1                     # rtt 回到 0.0x ms
```
